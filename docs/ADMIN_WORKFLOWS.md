# คู่มือผู้ดูแลระบบ — Admin Workflows (10.13B)

ผู้ดูแลระบบ (role `admin`) อนุมัติคำขอและจัดการวงจรชีวิตคนขับผ่านหน้าเว็บ/API
ไม่ต้องใช้ SQL ทุกการกระทำถูกบันทึกประวัติ (audit)

## 1. อนุมัติคำขอโอนย้ายนักเรียน

**เมนู:** คำขอโอนย้ายนักเรียน (`/admin/transfer-requests`)

- ดูรายการคำขอ (รออนุมัติ/อนุมัติแล้ว/ไม่อนุมัติ) → เปิดดูรายละเอียด
- ระบบแสดงคำเตือน: **รหัสซ้ำในโรงเรียนปลายทาง** และ **นักเรียนมีรถอยู่**
- **อนุมัติ** (กลยุทธ์ Option B): ปิดนักเรียนต้นทาง (soft-close) + สร้างนักเรียนปลายทางใหม่
  (รหัสใหม่อัตโนมัติ, คัดลอกผู้ปกครอง, ไม่ผูกรถ) — เก็บประวัติแยกตามโรงเรียน
- ถ้าโรงเรียนปลายทางมีรหัสนักเรียนซ้ำ → ระบบ **บล็อก** (FAILED) ไม่สร้างซ้ำ
- **ไม่อนุมัติ** ต้องใส่หมายเหตุ · การอนุมัติซ้ำปลอดภัย (idempotent)

## 2. อนุมัติคำขอเกี่ยวกับรถ

**เมนู:** คำขอเกี่ยวกับรถ (`/admin/vehicle-requests`)

- **ขอกู้คืนรถ (RESTORE):** อนุมัติแล้วระบบ **กู้คืนรถเดิม** (is_deleted=false, คำนวณ canonical ใหม่)
  - ถ้ามีรถทะเบียนเดียวกันใช้งานอยู่แล้ว → **บล็อก** “ไม่สามารถกู้คืนรถได้…” (ไม่สร้างซ้ำ)
  - ไม่แตะข้อมูลนักเรียน/คนขับ
- **ขอใช้รถที่มีอยู่ / ขอเพิ่มรถ / ขอตรวจสอบ:** เป็นข้อมูลแจ้งเพื่อทราบ (informational) ไม่แก้ข้อมูลรถ
- คำขอที่มาจากการนำเข้าจะแสดง **ชุด/แถว** ที่เกี่ยวข้อง · ต้องใส่หมายเหตุเมื่ออนุมัติ/ไม่อนุมัติ

## 3. เครื่องมือจัดการคนขับ (Driver lifecycle wizard)

**เมนู:** สุขภาพข้อมูลคนขับ (`/admin/driver-integrity`)

- **แดชบอร์ด:** รถยังไม่มีคนขับ / คนขับยังไม่มีรถ / บัญชีซ้ำ-ถูกปิด / ยังไม่ผูกโปรไฟล์ /
  งานชี้รถที่ปิด / รถมีคนขับซ้ำ / บล็อกเปิดใช้งานซ้ำ
- **เครื่องมือจัดการคนขับ** (กด → กรอก user id → **ตรวจสอบก่อนดำเนินการ (preflight)**):
  - **กู้คืนบัญชีคนขับ** — อนุญาตเฉพาะบัญชีหลัก (canonical); บัญชีซ้ำ (เช่น 408) จะถูก **บล็อก**
    พร้อมแจ้งบัญชีหลัก
  - **ย้ายคนขับไปรถใหม่** — สิ้นสุดงานเดิม + สร้างงานใหม่ (DB กันรถมีคนขับซ้ำ); ถ้ารถปลายทาง
    มีคนขับอยู่ ต้องติ๊กยืนยันสิ้นสุดงานเดิมก่อน
  - **ปิดใช้งานคนขับ** — สิ้นสุดงาน + ปิดบัญชี **ไม่ลบประวัติการรับส่ง**
- ทุกการกระทำต้องใส่เหตุผล และถูกบันทึกประวัติ

## 4. สุขภาพระบบ (Operations health)

**API:** `GET /api/admin/operations/health` (admin เท่านั้น)

- คืนสถานะรวม OK/WARN/CRITICAL + รายการตรวจ (ความถูกต้องข้อมูล, คนขับ-รถ, การนำเข้า,
  สำรองข้อมูล, ไมเกรชัน, ดิสก์) — ไม่มีข้อมูลส่วนบุคคล (PII)
- ใช้ตรรกะเดียวกับสคริปต์ `integrity-monitor.js` ที่รันอัตโนมัติทุกวัน 03:15
- ดูความหมาย WARN/CRITICAL และวิธีแก้ใน [OPERATOR_RUNBOOK.md](OPERATOR_RUNBOOK.md)

## ขอบเขตสิทธิ์ (RBAC)

- คำขออนุมัติ (โอนย้าย/รถ), วงจรชีวิตคนขับ, สุขภาพระบบ = **admin เท่านั้น** (โรงเรียนเข้าไม่ได้ → 403)
- โรงเรียนเห็น/จัดการเฉพาะข้อมูลและคำขอของโรงเรียนตนเอง
