## บริบท
ระบบ build ไปแล้ว ~95% ตาม `CLAUDE.md` และ **ขึ้น prod แล้ว**. "Cut phase" คือการ **ขีดเส้น MVP อย่างเป็นทางการ** ว่าอะไร "เปิดใช้จริง" ตอนเปิดเทอม vs อะไร "พับไว้เฟสหน้า" (ปิด feature flag ไว้) เพื่อลดความเสี่ยง + ไม่ติดกฎหมาย/ข้อมูลที่ยังไม่พร้อม.

**สำคัญ:** MVP ที่เลือก **เปิด + live อยู่แล้ว** ส่วนที่ตัด **ปิด flag อยู่แล้ว** — เอกสารนี้จึงเป็นการ *ยืนยันเส้นแบ่ง* ไม่ต้องรื้อระบบ.

หลักการเลือก: MVP ต้องครบ 1 วงจรทำงานรายวัน (รับเด็ก → ส่งเด็ก → ผู้ปกครองรู้ → ผู้บริหารเห็น → ปลอดภัย) และ **ไม่ติดกฎหมาย / ไม่พึ่งข้อมูลที่ยังไม่มี**.

## ✂️ CUT — ตัดไปเฟสหน้า (ปิด feature flag ไว้)

หลักการตัด: ของที่ (ก) รอ **กฎหมาย/DPO**, (ข) รอ **ข้อมูลสะสม** (GPS/route), หรือ (ค) เพิ่ม **ความซับซ้อนของกระบวนการ** ที่อาจทำให้ช่วงเปิดเทอมสะดุด.

| feature (flag) | ทำไมตัด | ต้องมีอะไรก่อนเปิด |
|----------------|---------|-------------------|
| QR + PDPA consent (`FEATURE_VEHICLE_QR`) | consent text ต้องให้ DPO/ทนายรีวิว (เสี่ยง PDPA) | ข้อความ consent ผ่านกฎหมาย + ทดสอบ |
| Parent consent gate (`FEATURE_PARENT_CONSENT_REQUIRED`) | ผูกกับ consent flow ข้างบน | เปิดพร้อม QR/consent |
| ETA รถถึงเมื่อไร (`FEATURE_ETA`) | ต้องมี GPS ไหลจริง + จูนความแม่น + LINE push | คนขับ ping GPS สม่ำเสมอ |
| Geofence แจ้งเตือน (`FEATURE_GEOFENCE`) | ต้องตั้งวง geofence + GPS จริง | GPS adoption + ตั้งจุด |
| จับรถออกนอกเส้นทาง (`FEATURE_ROUTE_DEVIATION`) | ต้องมี route baseline ≥ 3 วัน | สะสมข้อมูลเส้นทางจริง |
| เลือกกะคนขับ (`FEATURE_DRIVER_SHIFT_SELECTION`) | เพิ่มขั้นตอนให้คนขับ | ตัดสินใจว่าจำเป็นไหม |
| คนขับลงทะเบียนรถเอง + เอกสาร (`FEATURE_DRIVER_REGISTRATION`) | workflow กลับด้าน + อนุมัติหลายชั้น | ออกแบบ process + เทรน |
| QR ระดับ 3 (ข้อมูลอ่อนไหว) (`FEATURE_QR_LEVEL3`) | ต้อง DPO อนุมัติ | DPO sign-off |
| โหมดบังคับใช้ความปลอดภัย (`SAFETY_POLICY_MODE=enforce`) | คงไว้ OBSERVE — ยังไม่บล็อกรถ/คนขับ | ข้อมูลรับรองครบ + ตัดสินใจนโยบาย |

## 📏 เส้นแบ่ง (Cut Line)

```
        เปิดใช้ (MVP)                    │        ปิดไว้ (Cut → เฟสหน้า)
 ───────────────────────────────────────┼────────────────────────────────────
  auth · คนขับเช็กอิน · โรงเรียน          │  QR+consent · ETA · geofence
  เขต/จังหวัด · ขนส่งตรวจรถ               │  route-deviation · shift · driver-reg
  ผู้ปกครอง LINE · รายงาน · ops/backup    │  QR L3 · SAFETY=ENFORCE
```

- **MVP** = "การทำงานหลักรายวัน + กำกับดูแล + ปลอดภัยพื้นฐาน" — พิสูจน์แล้ว ไม่ติดกฎหมาย
- **Cut** = "ชั้นอัจฉริยะ (ETA/geofence/deviation) + QR/consent + workflow กลับด้าน" — รอ legal / ข้อมูล / การตัดสินใจ

เหตุผลที่เส้นนี้ดีสำหรับเปิดเทอม:
1. ฝั่ง MVP ทดสอบ + deploy แล้ว → ความเสี่ยงต่ำ
2. ของที่ตัดพึ่งปัจจัยภายนอก (DPO/GPS/route data) — ฝืนเปิดตอนนี้เป็นภาระ + เสี่ยง PDPA
3. เปิด MVP ก่อน → เก็บ GPS/ข้อมูลจริงระหว่างเทอม → มีข้อมูลพอค่อยเปิด ETA/geofence เฟสหน้า (เปิดทีละ flag ได้ ไม่ต้อง deploy ใหม่)

## ลำดับเปิด flag เฟสหน้า (แนะนำ)
1. **ETA** (หลัง GPS adoption นิ่ง ~2-4 สัปดาห์) — คุณค่าสูงต่อผู้ปกครอง, ไม่ติดกฎหมาย
2. **Geofence** (หลังตั้งจุด + GPS นิ่ง) — แจ้ง "รถถึงแล้ว"
3. **Route deviation** (หลังมี baseline ≥ 3 วัน)
4. **QR + PDPA consent** (หลัง DPO/ทนายรีวิว consent text — `consentText.js`) → แล้วค่อย `parentConsentRequired`, `qrLevel3`
5. **SAFETY=ENFORCE** (หลังข้อมูลรับรองรถ/คนขับครบ — ดูหน้า "ความพร้อมเปิดใช้งาน")
