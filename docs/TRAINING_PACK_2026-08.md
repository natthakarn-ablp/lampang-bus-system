# Training Pack 2026-08 — School Safe Connect ลำปาง

> **Historical snapshot (ติดป้าย 6 ก.ย. 2569):** เอกสารฉบับ 25 ส.ค. 2569 ถูกแทนที่ด้วยชุดคู่มืออบรมพร้อมภาพประกอบเมื่อ 26 ส.ค. 2569 และตารางขอบเขตในเอกสารนี้ไม่ตรงกับระบบจริงแล้ว — ตาราง "ขอบเขต MVP ที่เปิดใช้" ยังไม่มีงานลงทะเบียนรายชื่อเด็กในรถ (เมนู "รายชื่อเด็กในรถ" ของคนขับ และ "ตรวจลงทะเบียนรถ" ของโรงเรียน) ซึ่งเปิดใช้จริงบนระบบแล้ว ส่วนตาราง "สิ่งที่ยังไม่เปิดใช้เต็ม" ยังไม่ครอบคลุมงานที่เพิ่มเข้ามาภายหลังและ **ยังปิดอยู่บนระบบจริง** อีก 3 อย่าง คือ "เรื่องที่ต้องมีส่วนร่วม" (participation cases), "เลือกรถและเริ่มรอบ" ของคนขับ และการกู้คืนรหัสผ่านผู้ดูแลระบบผ่าน LINE ห้ามใช้ตารางทั้งสองนี้เป็นใบงานอบรมหรืออ้างเป็นขอบเขตระบบ
> ฉบับที่ใช้จริง: `docs/manual-training-2026-08/README.md` · ห้ามเปลี่ยนชื่อหรือลบไฟล์นี้ เพราะ `scripts/verify-100-readiness.js` และ `scripts/create-go-live-bundle.js` ตรวจหาไฟล์ชื่อนี้

สถานะเอกสาร: ใช้สำหรับอบรม/นำร่องก่อนเปิดใช้งานเต็มรูปแบบ
วันที่ปรับปรุง: 2026-08-25

## 1. Executive Brief

ระบบนี้เป็นระบบนิเวศดิจิทัลสำหรับบริหารความปลอดภัยรถรับส่งนักเรียนระดับจังหวัด เชื่อมข้อมูลโรงเรียน รถ คนขับ นักเรียน ผู้ปกครอง และหน่วยกำกับดูแลไว้ในระบบเดียว

ประโยชน์หลัก:

1. ผู้บริหารจังหวัดเห็นภาพรวมระดับจังหวัด/สังกัด/โรงเรียนได้จาก dashboard และรายงาน
2. โรงเรียนตรวจข้อมูลนักเรียน รถ และสถานะรับส่งได้ในระบบเดียว
3. คนขับเช็กอิน/เช็กเอาท์นักเรียนและแจ้งเหตุฉุกเฉินผ่านมือถือ
4. ผู้ปกครองผูกบัญชี LINE เพื่อดูสถานะบุตรหลานผ่าน LIFF
5. ขนส่งตรวจข้อมูลรถโดยไม่เห็นข้อมูลส่วนบุคคลของนักเรียนตามหลัก PDPA
6. ทุกการ export และ action สำคัญมี audit log สำหรับตรวจสอบย้อนหลัง

ขอบเขต MVP ที่เปิดใช้:

| โมดูล | ใช้งาน |
|---|---|
| Login + RBAC | แยกบทบาท admin, province, affiliation, school, driver, transport |
| Dashboard | จังหวัด/สังกัด/โรงเรียน/คนขับ/ขนส่ง |
| ข้อมูลหลัก | นักเรียน รถ คนขับ ผู้ปกครอง ผู้ใช้ |
| Import | นำเข้าข้อมูลโรงเรียนผ่าน flow ที่มี preview/validation |
| Operation รายวัน | เช็กอิน/เช็กเอาท์/สถานะวันนี้/เหตุฉุกเฉิน |
| Reports | รายวัน รายเดือน สรุปภาพรวม เชิงนโยบาย และ export |
| Audit | ตรวจสอบย้อนหลังตามสิทธิ์ |
| LINE Parent | ผูกบัญชีและดูสถานะผ่าน LIFF |

สิ่งที่ยังไม่เปิดใช้เต็ม:

| เรื่อง | เหตุผล |
|---|---|
| QR/consent gate | รอทบทวนถ้อยคำ PDPA โดย DPO/กฎหมาย |
| ETA/geofence/route deviation | รอ GPS adoption และข้อมูลเส้นทางจริง |
| SAFETY_POLICY_MODE=enforce | รอข้อมูลรับรองรถ/คนขับครบก่อนบังคับใช้ |

## 2. กติกาสำคัญระหว่างอบรม

- ห้ามใช้ข้อมูล production สำหรับกิจกรรมที่เพิ่ม แก้ ลบ import หรือ override
- กิจกรรม hands-on ที่เขียนข้อมูลต้องทำใน sandbox/UAT เท่านั้น
- ห้ามถ่าย/ส่งต่อข้อมูลส่วนบุคคลของเด็ก ผู้ปกครอง หรือ LINE user id
- ห้ามส่งรหัสผ่านผ่านไลน์กลุ่มหรือเอกสารอบรม
- ถ้าต้องแสดงตัวอย่าง ให้ใช้ข้อมูลจำลองหรือบัญชีทดสอบเท่านั้น
- ถ้าเจอข้อมูลผิดใน production ให้บันทึกเป็นรายการให้เจ้าของข้อมูลแก้ ไม่แก้สดระหว่างอบรม

## 4. Quick Guide: โรงเรียน

ใช้ทำอะไร:

- ดู dashboard โรงเรียนและสถานะวันนี้
- ตรวจ/จัดการข้อมูลนักเรียน รถ คนขับ ผู้ปกครอง
- import ข้อมูลแบบมี preview
- ดูรายงานรายวัน/รายเดือน/สรุป
- ตรวจ audit log ของโรงเรียน

ขั้นตอนใช้งานหลัก:

1. เข้า `https://schoolbuslampang.com`
2. Login ด้วยบัญชีโรงเรียน
3. ตรวจ dashboard ว่าจำนวนนักเรียน รถ และสถานะตรงกับข้อมูลจริง
4. เปิดเมนูนักเรียน/รถเพื่อตรวจข้อมูลที่ขาด
5. ใช้ import เฉพาะเมื่อมีไฟล์ที่ผ่านการตรวจแล้ว
6. เปิดรายงานรายวันเพื่อดูสถานะรับส่ง
7. ใช้ export เฉพาะกรณีจำเป็น และเก็บไฟล์ตามนโยบายหน่วยงาน

ข้อควรระวัง:

- ครูสายชั้นเห็นเฉพาะ scope ที่ได้รับสิทธิ์
- การ override/ยืนยันแทนคนขับต้องมีเหตุผลและใช้เฉพาะเหตุจำเป็น
- ข้อมูลผู้ปกครองที่ไม่มี phone หรือ phone ไม่ตรง จะผูก LINE ไม่สำเร็จ

## 5. Quick Guide: คนขับ

ใช้ทำอะไร:

- Login ด้วยทะเบียนรถหรือบัญชีที่ได้รับ
- ดูรายชื่อนักเรียนในรถที่ได้รับมอบหมาย
- เช็กอิน/เช็กเอาท์รายคนหรือทั้งคัน
- แจ้งเหตุฉุกเฉิน

ขั้นตอนใช้งานหลัก:

1. เปิดเว็บบนมือถือ
2. Login
3. ตรวจว่ารถและรายชื่อนักเรียนถูกต้อง
4. รอบเช้า กดเช็กอินเมื่อนักเรียนขึ้นรถ/ถึงตามกระบวนการที่กำหนด
5. รอบเย็น กดเช็กเอาท์เมื่อนักเรียนลงรถ/ส่งถึงจุดหมาย
6. กรณีฉุกเฉิน ใช้ปุ่มฉุกเฉินและกรอกข้อมูลให้ชัดเจน

ข้อควรระวัง:

- ห้ามกดฉุกเฉินเล่น
- ถ้ารายชื่อนักเรียนไม่ตรง ให้แจ้งโรงเรียน ไม่แก้เองนอกระบบ
- ถ้าเน็ตหลุด ให้แจ้งโรงเรียน/ผู้ประสานงานทันที และกลับมา sync เมื่อใช้งานได้

## 6. Quick Guide: ผู้ปกครอง LINE

ใช้ทำอะไร:

- เพิ่มเพื่อน LINE OA
- ผูกบัญชีด้วยข้อมูลที่โรงเรียนบันทึกไว้
- ดูสถานะบุตรหลานผ่าน LIFF

ขั้นตอนใช้งานหลัก:

1. เพิ่มเพื่อน LINE OA ของระบบ
2. พิมพ์ `ผูกบัญชี`
3. เปิดฟอร์มผูกบัญชี
4. กรอกข้อมูลที่ระบบต้องการ เช่น เบอร์โทรและรหัสนักเรียน
5. เมื่อผูกสำเร็จ กดดูสถานะได้ผ่าน LINE/LIFF

ข้อควรเข้าใจ:

- สถานะรับส่งประจำวันให้ดูผ่าน LIFF เป็นหลัก
- LINE push ใช้ตามนโยบายจังหวัด โดย MVP แนะนำให้ใช้กับเหตุสำคัญ/exception
- ถ้าผูกไม่ได้ มักเกิดจากเบอร์โทรในระบบไม่ตรงหรือยังไม่มี approved parent

## 7. Quick Guide: จังหวัด/สังกัด

ใช้ทำอะไร:

- ดูภาพรวมโรงเรียน นักเรียน รถ คนขับ
- ติดตามสถานะรายวัน
- ดูรายงานรายเดือน/สรุป/เชิงนโยบาย
- ตรวจ audit log ในขอบเขตสิทธิ์

ขั้นตอนใช้งานหลัก:

1. Login ด้วยบัญชี province หรือ affiliation
2. เปิด dashboard และตรวจ KPI ภาพรวม
3. Drill down ไปโรงเรียน/สังกัดที่มีความเสี่ยง
4. เปิดรายงานรายวัน/รายเดือน
5. Export เฉพาะข้อมูลที่จำเป็นต่อการประชุมหรือกำกับดูแล

ข้อควรระวัง:

- รายงานวันนี้ขึ้นกับข้อมูลใน `daily_status`
- ถ้าวันนั้นยังไม่มี check-in ระบบจะแสดง 0 ไม่ใช่ระบบล่ม
- รายงานย้อนหลังเกิน retention อาจต้องใช้ snapshot/report archive เพิ่มในเฟส governance

## 8. Quick Guide: ขนส่ง

ใช้ทำอะไร:

- ตรวจข้อมูลรถและเอกสารที่เกี่ยวข้อง
- บันทึกผลตรวจรถ
- ดู pickup map แบบไม่แสดงข้อมูลส่วนบุคคลนักเรียน

ข้อควรระวัง:

- บทบาทขนส่งไม่ควรเห็นชื่อนักเรียนหรือจำนวนรายคน
- หากพบข้อมูลนักเรียนในหน้าขนส่ง ให้บันทึกเป็น incident ทันที
- การรับรองรถต้องอิงหลักฐานจริงและบันทึกในระบบ

## 9. UAT Sign-off Summary

ก่อนเริ่ม UAT ให้สร้างชุดหลักฐานแยกตามบทบาท:

```bash
node scripts/create-uat-evidence-pack.js --mode sandbox --base-url https://schoolbuslampang.com
```

ใช้ไฟล์ใน `outputs/uat-evidence/<timestamp>/` เป็นใบงานและที่อยู่หลักฐานของแต่ละบทบาท

หลังกรอกหลักฐานครบ ให้ตรวจด้วย:

```bash
node scripts/scan-uat-evidence-safety.js outputs/uat-evidence/<timestamp>
node scripts/summarize-uat-evidence.js outputs/uat-evidence/<timestamp>
node scripts/create-go-live-signoff-draft.js outputs/uat-evidence/<timestamp>
node scripts/validate-uat-evidence-pack.js outputs/uat-evidence/<timestamp>
```

ไฟล์ `outputs/uat-safety/<timestamp>/summary.md` ใช้ตรวจว่า evidence ไม่มี secret/CID/phone/LINE user id ในข้อความก่อนส่งลงนาม

ไฟล์ `outputs/uat-status/<timestamp>/missing-items.csv` ใช้แบ่งงานติดตามผู้ทดสอบแต่ละบทบาทได้ โดยไม่ต้องเปิดหลักฐานที่อาจมีข้อมูลอ่อนไหวทั้งหมด

ไฟล์ `outputs/signoff-draft/<timestamp>/role-transfer.csv` ใช้ช่วยย้ายผลบทบาทเข้าสู่เอกสาร sign-off โดยต้องให้ UAT lead ตรวจหลักฐานก่อนเสมอ

## 11. Support Flow

| ระดับ | ตัวอย่าง | ผู้รับผิดชอบเริ่มต้น |
|---|---|---|
| Critical | ระบบล่ม, login ไม่ได้ทุกคน, DB disconnected | Operator + dev |
| High | คนขับเช็กอินไม่ได้, LINE parent ใช้ไม่ได้ทั้งโรงเรียน | Operator + โรงเรียน |
| Medium | รายงานตัวเลขไม่ตรง, บัญชีรายคนมีปัญหา | Admin ระบบ |
| Low | คำสะกด, คู่มือ, feature request | ทีมโครงการ |

เวลารายงานปัญหาให้แนบ:

- URL หรือหน้าจอที่เกิดปัญหา
- วันเวลาแบบเวลาไทย
- บทบาทผู้ใช้
- screenshot ที่ไม่เปิดเผยข้อมูลเกินจำเป็น
- ข้อความ error ถ้ามี
