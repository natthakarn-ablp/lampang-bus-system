## 1. เหตุผลที่พัฒนา

ข้อมูลรถรับส่งเดิมกระจายอยู่คนละหน่วยงาน:

- โรงเรียนรู้ว่ามีนักเรียนใช้รถคันใด แต่ไม่ทราบสถานะการตรวจรถทั้งหมด
- ขนส่งรู้ว่ารถคันใดเข้าตรวจ แต่ไม่ทราบว่ารถให้บริการโรงเรียนใดและมีผู้โดยสารประมาณเท่าใด
- อบจ. ไม่เห็นภาพรวมว่ารถแต่ละคันรับนักเรียนจากที่ใด ใช้ร่วมกันกี่โรงเรียน และใครเป็นคนขับจริงในแต่ละรอบ

ระบบใหม่นี้ทำหน้าที่เป็นจุดเชื่อมข้อมูลระหว่างโรงเรียน อบจ. และสำนักงานขนส่งจังหวัดลำปาง โดยไม่ต้องพึ่ง API ของกรมการขนส่งทางบกส่วนกลางในระยะแรก เจ้าหน้าที่ขนส่งจังหวัดสามารถตรวจรถจริงและลงผลรับรองในระบบ อบจ. ได้โดยตรง

## 2. สิ่งที่เพิ่มเข้ามา

### 2.1 ใบส่งตรวจรถแบบรวมหลายโรงเรียน

- โรงเรียนใดก็ได้ที่มีนักเรียนใช้รถคันนั้นสามารถสร้างใบส่งตรวจได้
- รถหนึ่งคันมีคำขอที่กำลังดำเนินการได้เพียงชุดเดียวต่อภาคเรียน
- ระบบรวมข้อมูลทุกโรงเรียนที่ใช้รถคันเดียวกันโดยอัตโนมัติ
- แสดงจำนวนผู้โดยสารรอบเช้า รอบเย็น และจำนวนสูงสุดต่อรอบ
- แสดงพื้นที่รับส่งโดยสรุป
- สร้างเลขคำขอและ QR สำหรับเปิดเอกสาร
- โรงเรียนที่ใช้รถร่วมกันสามารถดูสถานะคำขอเดียวกันได้ ไม่ต้องทำเอกสารซ้ำ

ข้อมูลที่ส่งให้ขนส่งไม่มีรายชื่อนักเรียน ชื่อผู้ปกครอง เบอร์โทร หรือรหัสประจำตัว

### 2.2 คิวตรวจรถสำหรับเจ้าหน้าที่ขนส่ง

- ค้นหาคำขอด้วยทะเบียนรถ เลขคำขอ หรือโรงเรียน
- กรองตามสถานะ เช่น รอรับรถ กำลังตรวจ ต้องแก้ไข ผ่าน และไม่ผ่าน
- ดูข้อมูลรถ ความจุรับรอง จำนวนผู้โดยสารสูงสุด โรงเรียน พื้นที่รับส่ง และกลุ่มคนขับ
- เริ่มการตรวจครั้งใหม่โดยไม่แก้ทับประวัติครั้งก่อน
- ใช้ checklist แบบมีเวอร์ชัน
- บังคับให้กรอกผลหัวข้อที่จำเป็นครบทุกข้อ
- หัวข้อที่ไม่ผ่านต้องระบุรายละเอียด
- ผลรวมรองรับ `PASSED`, `FAILED`, `NEEDS_FIX` และ `PENDING`
- ผลผ่านต้องระบุวันหมดอายุการรับรอง

### 2.3 การคำนวณสิทธิ์ใช้งานรถ

รถจะพร้อมใช้งานเมื่อผ่านเงื่อนไขต่อไปนี้:

1. ผลตรวจล่าสุดผ่านและยังไม่หมดอายุ
2. ประกันภัย ทะเบียน พ.ร.บ. และภาษียังใช้ได้
3. ความจุรับรองไม่น้อยกว่าจำนวนผู้โดยสารสูงสุดต่อรอบ
4. มีคนขับที่ได้รับอนุญาตอย่างน้อยหนึ่งคน
5. ใบอนุญาตของคนขับได้รับการรับรองและยังไม่หมดอายุ
6. รถไม่ถูกระงับใช้งาน

สถานะรถประกอบด้วย:

- `UNVERIFIED` — ยังไม่มีข้อมูลเพียงพอ
- `ELIGIBLE` — พร้อมใช้งาน
- `EXPIRING` — พร้อมใช้งานแต่มีรายการใกล้หมดอายุ
- `INELIGIBLE` — ยังไม่ผ่านเงื่อนไข
- `SUSPENDED` — ถูกระงับใช้งาน

เมื่อเพิ่มคนขับ รับรองใบอนุญาต หรือเปลี่ยนข้อมูลที่เกี่ยวข้อง ระบบจะคำนวณสถานะรถใหม่ทันที ไม่ต้องรอการตรวจรอบถัดไป

### 2.4 คนขับหลักและคนขับสำรอง

- รถหนึ่งคันมีคนขับหลักและคนขับสำรองได้หลายคน
- คนขับหนึ่งคนได้รับอนุญาตให้ขับรถได้หลายคัน
- การมอบหมายระบุบทบาท `PRIMARY` หรือ `BACKUP`
- กำหนดวันเริ่มต้นและวันสิ้นสุดสิทธิ์ได้
- เจ้าหน้าที่ขนส่งหรือผู้ดูแลสามารถรับรองเลขใบอนุญาต ประเภทใบอนุญาต วันหมดอายุ และเลขอ้างอิงได้
- การเพิ่มคนขับสำรองไม่ยกเลิกคนขับเดิมของรถ

### 2.5 บันทึกคนขับจริงในแต่ละรอบ

คนขับต้องเลือกรถที่ได้รับอนุญาตก่อนเริ่มงาน ระบบบันทึก:

- คนขับจริง
- รถที่ใช้จริง
- คนขับหลักหรือสำรอง
- รอบเช้า รอบเย็น หรือรอบอื่น
- เวลาเริ่มและเวลาสิ้นสุด

ระบบป้องกัน:

- คนขับคนเดียวเปิดงานพร้อมกันสองคัน
- รถคันเดียวมีคนขับพร้อมกันสองคน
- คนขับที่ไม่ได้รับอนุญาตเลือกขับรถ
- คนขับใบอนุญาตหมดอายุเริ่มรอบ
- รถที่ไม่ผ่านเงื่อนไขความปลอดภัยเริ่มรอบ

## 6. การทำงานโดยไม่มี DLT API

ปัจจุบันระบบใช้เจ้าหน้าที่ขนส่งจังหวัดเป็นผู้ตรวจและลงผลโดยตรง แหล่งรับรองถูกเก็บใน `provider_type` เพื่อรองรับช่องทางอื่นในอนาคต:

- `DLT_OFFICER`
- `PAO_INSPECTOR`
- `PRIVATE_INSPECTION_CENTER`
- `SIGNED_BATCH_FILE`
- `DLT_CENTRAL_API`

หากได้รับ API key จากส่วนกลางภายหลัง สามารถเพิ่ม adapter สำหรับ `DLT_CENTRAL_API` ได้โดยไม่ต้องเปลี่ยน workflow หรือโครงสร้างคำขอเดิม

## 7. ความเป็นส่วนตัวและความปลอดภัย

- Snapshot ของคำขอเก็บเฉพาะจำนวนผู้โดยสาร ไม่เก็บ student ID หรือรายชื่อ

- QR สาธารณะไม่แสดงเจ้าของรถ ชื่อคนขับ เบอร์โทร นักเรียน ผู้ปกครอง หรือ URL หลักฐาน
- การอ่านข้อมูลอ่อนไหวระดับเจ้าหน้าที่ยังคงเขียน audit log
- การเปลี่ยนสถานะคำขอ การตรวจรถ การมอบหมายคนขับ และการเริ่ม/จบรอบเขียน audit log
- การตรวจแต่ละครั้งเป็น append-only ไม่แก้ทับประวัติเดิม

## 8. Feature flag สำหรับ rollout คนขับหลายคัน

เพิ่มตัวแปร:

```env
FEATURE_DRIVER_SHIFT_SELECTION=false
```

ค่าเริ่มต้นเป็น `false` เพื่อไม่ให้กระทบบัญชีคนขับเดิม เมื่อเปิดเป็น `true` การเช็กอิน ตำแหน่งรถ และเหตุฉุกเฉินจะใช้รถจาก active shift ที่คนขับเลือกเท่านั้น

ก่อนเปิด flag ต้องตรวจว่า:

1. รัน migration 039 แล้ว
2. บัญชีคนขับมี `users.driver_id`
3. ลงข้อมูลใบอนุญาตและสถานะรับรองแล้ว
4. มอบหมายรถหลัก/สำรองครบแล้ว
5. ทดลอง flow เริ่มรอบและสิ้นสุดรอบกับกลุ่มนำร่อง
