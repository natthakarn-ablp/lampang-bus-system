# UPDATE-2026-06-23 — Intelligent Tracking Layer (Phase 11A)

> เอกสารนี้บันทึกการเพิ่มฟีเจอร์ใหม่ 3 ตัวที่เชื่อมทุกระบบเข้าด้วยกัน
> โดยใช้ GPS feed ที่มีอยู่แล้ว (vehicle_latest_locations) เป็นแหล่งข้อมูลหลัก

---

## ภาพรวม

เทียบกับ Top 5 ระบบ school bus tracking ของโลก (Transfinder, Here Comes
the Bus, Zūm Ride, Zonar, Edulog) พบว่า Lampang Bus System มีฟีเจอร์หลัก
ครบแล้ว (live GPS, check-in/out, parent notification, multi-role RBAC,
vehicle inspection, driver shift, emergency) แต่ยังขาด 3 ความสามารถที่
ระบบ top ทุกตัวมี และใช้ข้อมูลที่มีอยู่แล้ว (ไม่ต้องลงทุน hardware):

1. **ETA prediction** — คำนวณเวลาถึงแต่ละจุดรับ-ส่ง
2. **Geofencing auto-alert** — รถเข้า/ออก zone → แจ้งอัตโนมัติ
3. **Off-route / delay detection** — รถเบี่ยง/ล่าช้า → แจ้ง school + province

ทั้งสามถูกออกแบบให้ **เชื่อมทุกระบบ**: driver ส่ง GPS → backend คำนวณ
→ parent ได้ ETA + geofence alert ผ่าน LINE → school/province เห็น
deviation บน dashboard → admin จัดการ geofences ได้

## สิ่งที่ทำในวันนี้ (2026-06-23)

### 1. Database — Migration 040

**ไฟล์:** `backend/migrations/040_intelligent_tracking.sql`

ตารางใหม่ 6 ตัว:

| ตาราง | หน้าที่ |
|---|---|
| `vehicle_location_history` | GPS trail แบบ append-only (เดิมมีแค่ latest-only) |
| `geofences` | จุดเตือนภัย (circle: center + radius) |
| `geofence_events` | log การเข้า/ออก geofence |
| `route_baselines` | เส้นทาง/เวลาเฉลี่ยต่อรถต่อsessionต่อday_of_week |
| `route_deviations` | log การเบี่ยง/ล่าช้า/หยุดนิ่ง |
| `eta_predictions` | cached ETA ต่อ (vehicle, pickup_point, session, date) |

`audit_logs.action` enum ขยายเพิ่ม: `GEOFENCE_ENTER`, `GEOFENCE_EXIT`,
`ROUTE_DEVIATION`, `ETA_REFRESH`

### 2. Backend — Feature Flags

- `backend/src/routes/driver.routes.js` — `POST /vehicle-location` หลัง

### 8. การเชื่อมระบบ (Integration Map)

```
Driver app
  │
  ▼ POST /api/driver/vehicle-location (GPS)
  │
  ├──► vehicle_latest_locations (UPSERT — เดิม)
  ├──► vehicle_location_history (INSERT — ใหม่)
  │
  ├──► [FEATURE_ETA] eta.service.refreshForVehicle()
  │      └──► eta_predictions (UPSERT)
  │           │
  │           ▼
  │     Parent LIFF: GET /api/parent/children/:id/eta
  │     School/Admin: GET /api/eta/vehicle/:id
  │
  ├──► [FEATURE_GEOFENCE] geofence.service.checkForVehicle()
  │      ├──► geofence_events (INSERT on transition)
  │      ├──► audit_logs (GEOFENCE_ENTER/EXIT)
  │      ├──► LINE push → parents (รถถึงจุด/ออกจุด)
  │      └──► operationsAlert webhook → school/province
  │
  └──► [FEATURE_ROUTE_DEVIATION] routeDeviation.service.checkForVehicle()
         ├──► route_deviations (INSERT on new violation)
         ├──► audit_logs (ROUTE_DEVIATION)
         └──► operationsAlert webhook → school/province
              │
              ▼
        Admin/Province dashboard: /admin/route-deviations
```

## วิธีเปิดใช้งาน

### ขั้นที่ 1 — รัน migration

```bash
mysql -u root -p lampang_bus < backend/migrations/040_intelligent_tracking.sql
```

### ขั้นที่ 2 — เปิด feature flags ใน `.env`

```env
FEATURE_ETA=true
FEATURE_GEOFENCE=true
FEATURE_ROUTE_DEVIATION=true
```

### ขั้นที่ 3 — รีสตาร์ท backend

```bash
pm2 restart schoolbus-backend
```

backend จะตรวจ migration 040 ตอน boot — ถ้าตารางขาดจะ exit(1) ทันที
พร้อมข้อความบอกว่าขาดตารางอะไร

### ขั้นที่ 4 — สร้าง geofences เริ่มต้น

เข้า `/admin/geofences` → กด "สร้างอัตโนมัติ" → ระบบจะสร้าง geofence
รอบทุกจุดรับ-ส่ง (150m) และทุกโรงเรียน (300m) ที่ยังไม่มี

### ขั้นที่ 5 — (ทางเลือก) เรียนรู้ baseline

ระบบ route deviation จะเริ่มทำงานหลังมีข้อมูล GPS พอสมควร (≥ 3 วัน)
จึงจะมี baseline ให้เทียบ ก่อนหน้านั้นจะมีแค่ STALLED detection
(ไม่ต้องใช้ baseline)

## ข้อจำกัด / Known Limitations

1. **ETA คำนวณจาก speed + haversine ตรง** — ไม่ได้ใช้ road network
   หรือ traffic data จริง (เหมือน Here Comes the Bus ที่มี traffic API)
   สำหรับ context จังหวัดลำปาง (รถวิ่งในเมือง/ชานเมือง) ความแม่นยำพอใช้
   หากต้องการแม่นขึ้นต้องเชื่อม Google Maps Routing API หรือ OSRM

2. **Geofence เป็นวงกลม** — ใช้ center + radius (haversine) ไม่ใช่
   polygon ตามรูปทรงจริง ฟิลด์ `polygon_geojson` เตรียมไว้ในตาราง
   สำหรับอัปเกรดภายหลัง แต่ service ปัจจุบันใช้ radius

3. **Route baseline ต้องมีข้อมูล ≥ 3 วัน** — ก่อนนั้นจะมีแค่ STALLED
   detection ที่ทำงานได้ (ไม่ต้องใช้ baseline)

4. **History table โตเร็ว** — ถ้า driver ส่ง GPS ทุก 15s × 55 คัน × 10 ชม
   = ~132,000 rows/day ต้องรัน prune job ทุกคืน (retention 30 วัน
   default = ~4M rows สูงสุด)

5. **LINE push quota** — geofence notifications ใช้ push quota ของ
   LINE OA (200 messages/ชม. สำหรับ free plan) ถ้ารถเข้า/ออกจุดเยอะ
   อาจชน quota ต้องเลือก trigger_on ระมัดระวัง (เช่น ENTER เท่านั้น
   สำหรับจุดรับ-ส่ง, BOTH สำหรับโรงเรียน)
