# Workflow ตรวจสอบสิทธิ์คนขับ

ใช้ก่อนเผยแพร่ทุกครั้งที่แก้หน้าเช็กชื่อ รถที่ได้รับมอบหมาย จุดรับส่ง โปรไฟล์ เอกสาร ตำแหน่งรถ เหตุฉุกเฉิน หรือ role guard ของคนขับ ตรวจทั้งเมนู, API ฝั่ง server, ขอบเขตรถ/นักเรียน และ audit โดยไม่ใช้ข้อมูลจริงเขียนทดสอบบน production

## สิทธิ์ที่ต้องได้

| หมวด | คนขับทำได้ | ขอบเขตบังคับฝั่ง server |
|---|---|---|
| ดู | รถที่ได้รับอนุญาต รอบงาน รายชื่อนักเรียน จุดรับส่ง สถานะวันนี้ การลา โปรไฟล์ คำขอ และสถานะส่งตรวจรถ | รถที่กำลังปฏิบัติงานหรือรถที่ผูกกับบัญชี; รายชื่อนักเรียนไม่มีเลขประจำตัวและเบอร์ผู้ปกครอง |
| แก้ไข | เช็กขึ้น/ลงรถ บันทึกลา ตรวจรถก่อนออก จัดจุดรับส่ง แก้โปรไฟล์ ส่งตำแหน่ง อัปโหลดเอกสาร และสร้างคำขอ | รถของตนเท่านั้น; นักเรียนต้องอยู่ในรถ; คำขอรายชื่อยังต้องให้โรงเรียนอนุมัติ |
| เหตุฉุกเฉิน | ส่งเหตุพร้อมตำแหน่งเมื่อมี โดยต้องส่งได้แม้ GPS หรือ safety policy มีปัญหา | ระบบผูกรถจากบัญชีและกันการกดซ้ำ |
| อนุมัติ | ไม่มีสิทธิ์อนุมัติคำขอรายชื่อ เอกสาร ผลตรวจรถ หรือผู้ใช้ | โรงเรียน ขนส่ง หรือ admin เป็นผู้อนุมัติตามประเภทงาน |
| ส่งออก | ไม่มีสิทธิ์ส่งออกรายงาน | `/api/reports/*` และ export ทุกชนิดต้องถูกปฏิเสธ |

การเห็นรายชื่อโรงเรียนใช้สำหรับเลือกปลายทางของคำขอเท่านั้น ไม่ให้สิทธิ์แก้ข้อมูลโรงเรียน นักเรียนจะเข้ารถจริงเมื่อโรงเรียนอนุมัติ

## หน้าที่ต้องตรวจให้ครบ

ตารางนี้เป็นรายการครบของหน้า frontend ที่ role `driver` เปิดได้จาก route graph ปัจจุบัน ต้องตรวจทั้งจอ 320, 375, 768 และ 1280 พิกเซล โดยไม่ทำรายการเขียนซ้ำเพื่อทดสอบหน้าจอ

| กลุ่ม | เส้นทาง | สิ่งที่ต้องเห็น/เงื่อนไข |
|---|---|---|
| งานประจำ | `/driver` | ภาพรวมวันนี้ ตรวจรถก่อนออก รายชื่อและสถานะเช็กชื่อของรถตนเอง |
| งานประจำ | `/driver/roster` | รายชื่อนักเรียนของรถตนเอง แยกรอดำเนินการ/เสร็จแล้ว และไม่มีเลขประจำตัวหรือเบอร์ผู้ปกครอง |
| งานประจำ | `/driver/pretrip` | แบบตรวจรถก่อนออกและสถานะที่บันทึกวันนี้ |
| งานประจำ | `/driver/pickup-map` | แผนที่และจุดรับส่งของรถตนเอง |
| ขึ้นทะเบียน | `/driver/vehicle-registration` | รายชื่อเด็กในรถและเอกสาร เมื่อ `FEATURE_DRIVER_REGISTRATION=true` |
| ขึ้นทะเบียน | `/driver/applications` | ยื่นคำขอและติดตามสถานะตรวจรถ เมื่อ `FEATURE_DRIVER_REGISTRATION=true` |
| ความปลอดภัย | `/driver/emergency` | ฟอร์มเหตุฉุกเฉิน ต้องไม่ส่งเหตุจริงระหว่าง smoke test |
| บัญชี | `/driver/profile` | โปรไฟล์ รถ เอกสาร และเปลี่ยนรหัสผ่านของตนเอง |
| นโยบาย | `/my-policy` | ข้อความตาม role คนขับและบริบทการทำงาน |
| การมีส่วนร่วม | `/participation`, `/participation/new`, `/participation/summary` | รายการ ยื่นเรื่อง และสรุปเฉพาะ scope ของคนขับ เมื่อ `FEATURE_PARTICIPATION_CASES=true` |
| เส้นทางเดิม | `/driver/requests` | เปิดตรงได้แต่ซ่อนจากเมนูเมื่อหน้ารายชื่อเด็กแบบรวมเปิดอยู่ เพื่อไม่ให้คนขับสับสนสองขั้นตอน |
| เส้นทางเดิม | `/driver/leaves` | เปลี่ยนกลับ `/driver`; การลาอยู่ในหน้าหลักแล้ว |
| ฟีเจอร์ปิด | `/driver/shift` | ซ่อนจากเมนูเมื่อ `FEATURE_DRIVER_SHIFT_SELECTION=false`; ห้ามบังคับให้เลือกรถซ้ำ |
| ฟีเจอร์ปิด | `/driver/consent` | เมื่อ `FEATURE_VEHICLE_QR=false` ต้องไป `/my-policy` และต้องไม่เรียก `/api/consent/*`; เมื่อเปิด flag จึงแสดงฟอร์มความยินยอม QR |

เมนูมือถือที่คนขับใช้เป็นหลักต้องมี 4 รายการ: หน้าแรก, รายชื่อเด็ก, ฉุกเฉิน และโปรไฟล์ แต่ละปุ่มต้องสูงอย่างน้อย 44 พิกเซล ไม่มี horizontal overflow และสถานะ active ต้องอ่านได้โดยไม่พึ่งสีอย่างเดียว

## ผลตรวจหน้าเว็บล่าสุด 19 ตุลาคม 2569

- ตรวจ 16 เส้นทาง × 4 ขนาดจอ รวม 64 กรณีด้วยบัญชีและข้อมูลจำลอง; ไม่ mock API และบล็อกการเชื่อมต่อภายนอก
- 60 กรณีผ่านในรอบแรก พบ `/driver/consent` เรียก API 404 ทั้ง 4 ขนาดจอเมื่อ Vehicle QR ปิด
- แก้ route ให้ตาม feature flag แล้วตรวจซ้ำ 4/4 ผ่าน: ไป `/my-policy`, ไม่เรียก consent API, ไม่มี overflow หรือ loading ค้าง
- ตรวจ URL ต่างบทบาท 6 เส้นทาง × 2 ขนาดจอ รวม 12 กรณี ถูกปฏิเสธครบ ได้แก่ admin, reports, school, transport, province และ affiliation
- Route contract ฝั่ง server ตรวจ 58 route: VIEW 20, EDIT 27, EMERGENCY 1, DENY 8 และ CONDITIONAL 12; findings เป็นศูนย์
- หลักฐานการเขียนเดิมใช้ข้อมูลจำลองและไม่ replay: เช็กชื่อขึ้น/ลงรถ, ตรวจรถก่อนออก, เหตุฉุกเฉินหนึ่งเหตุ, shift, override, เอกสารและ lifecycle ตามไฟล์ UAT เดิม

ผลนี้เป็น technical verification บน sandbox ยังต้องให้คนขับจริงตรวจรับถ้อยคำ ลำดับงาน และความเข้าใจบนมือถือของตนเอง

## ขั้นตอนตรวจ

1. **ตรึงรุ่นและสถานะ** — บันทึก commit, เวลา, health, DB connectivity, PID/restart, deploy lock และ feature flags `DRIVER_REGISTRATION`, `DRIVER_SHIFT_SELECTION`, `ETA`, `GEOFENCE`, `ROUTE_DEVIATION`
2. **ตรวจ route graph** — ใน `backend` รัน `npm run audit:driver-permissions` ผลต้อง `PASS` และ findings เป็นศูนย์ สคริปต์นี้ไม่ต่อฐานข้อมูล
3. **ตรวจเมนู** — บัญชีคนขับเห็นหน้าเช็กชื่อ จุดรับส่ง คำขอ/รายชื่อรถ สถานะส่งตรวจ เหตุฉุกเฉิน โปรไฟล์ และนโยบายตาม flags ต้องไม่เห็นรายงาน แอดมิน ขนส่ง หรือข้อมูลโรงเรียน
4. **ตรวจ scope อ่าน** — ฐานจำลองต้องยืนยันว่ารายชื่อ จุดรับส่ง การลา โปรไฟล์ เอกสาร คำขอ และ timeline มาจากรถ/ผู้ใช้ของคนขับเท่านั้น เปลี่ยน id ใน URL แล้วต้อง 403/404 โดยไม่เผยข้อมูลว่า record มีอยู่หรือไม่
5. **ตรวจ scope เขียน** — ใช้ fixture ใหม่หนึ่งชุด ทดสอบเช็กชื่อ/ลา/จุดรับส่ง/เอกสารกับรถตนเองสำเร็จ และใช้ student, vehicle, point, leave, shift, document ของคนอื่นแล้วต้องไม่เปลี่ยนฐานข้อมูล
6. **ตรวจเช็กชื่อ** — ทดสอบรายคน, ทั้งคัน, กดซ้ำ, ลา, ยกเลิกรายการของตน พร้อม transaction/audit และสถานะประจำวัน ห้าม replay fixture เดิมหรือเขียน production
7. **ตรวจเหตุฉุกเฉิน** — ทดสอบ idempotency และกรณีไม่มี GPS ใน sandbox เท่านั้น เหตุต้องถูกบันทึกแม้การแจ้งเตือนภายนอกล้มเหลว ห้ามส่ง LINE จริงระหว่าง UAT หากไม่มีชุดทดสอบแยก
8. **ตรวจเอกสาร** — อัปโหลดเฉพาะชนิด/ขนาดที่อนุญาต, magic-byte ผ่าน, เปิดได้เฉพาะไฟล์ของตนหรือรถที่ใช้งาน และ audit ต้องสำเร็จก่อนปล่อยไฟล์ เอกสารที่อนุมัติแล้วลบเองไม่ได้
9. **ตรวจการปฏิเสธ** — บัญชีคนขับเรียก `/api/admin/*`, `/api/reports/*`, `/api/school/*`, `/api/transport/*`, `/api/province/*`, `/api/affiliation/*` ต้อง 403/404 และไม่มีข้อมูลตอบกลับ
10. **ตรวจ production แบบอ่านอย่างเดียว** — หลังเผยแพร่ ตรวจหน้าเว็บ 200, API ไม่เข้าสู่ระบบ 401, เมนูและหน้าหลักด้วยบัญชีคนขับจริง ห้ามสร้าง check-in, เหตุฉุกเฉิน, จุดรับส่ง หรือคำขอบนข้อมูลจริงเพื่อทดสอบ

## เกณฑ์ผ่าน

- Contract route graph และชุด scope regression ผ่านทั้งหมด
- เปลี่ยน id/body/query ไม่สามารถข้ามรถหรือผู้ใช้ที่ผูกกับ token
- roster ไม่มี `cid`, `cid_hash`, เบอร์นักเรียนหรือเบอร์ผู้ปกครอง
- ไม่มี route ส่งออก รายงาน หรืออนุมัติที่คนขับเข้าถึงได้
- งานฉุกเฉินไม่ถูก policy ปิดกั้น และงานอื่นยังผ่าน safety policy ตาม flags
- ผู้รับผิดชอบคนขับตรวจรับภาษาหน้าจอและการใช้งานบนมือถือจริงด้วยตนเอง
