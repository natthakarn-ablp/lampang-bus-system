⚠️ ถ้าติดปัญหา:

  • ขึ้น "กรุณาเปลี่ยนรหัสผ่านก่อนใช้งานระบบ" → ต้องเปลี่ยนรหัสให้เสร็จก่อน จึงใช้เมนูอื่นได้
  • ไม่มีการรีเซ็ตรหัสผ่านด้วยตัวเอง (self-service) — หน้าเข้าสู่ระบบมีแถบกดเปิด-ปิด "ลืมรหัสผ่านหรือเข้าใช้งานไม่ได้" อยู่ใต้ปุ่ม "เข้าสู่ระบบ" กดแล้วจะแสดงกล่อง "ช่องทางขอความช่วยเหลือ" ซึ่งบอกเพียงว่า "โรงเรียนและคนขับ: ติดต่อผู้ดูแลบัญชีของโรงเรียน" และ "ต้นสังกัด ขนส่ง และจังหวัด: ติดต่อผู้ดูแลระบบระดับจังหวัด" (ยังไม่เปิดการรีเซ็ตผ่าน LINE จึงไม่มีลิงก์นั้นแสดง) ถ้า admin ลืมรหัส ต้องให้ admin อีกคน รีเซ็ตให้ที่หน้า "จัดการผู้ใช้งาน" (ควรมี admin สำรองอย่างน้อย 2 บัญชีเสมอ; ถ้าเป็น admin คนเดียวและถูกล็อกออก ต้องพึ่งผู้ดูแลเซิร์ฟเวอร์แก้ที่ฐานข้อมูล)
  • ขณะ admin สร้าง/รีเซ็ตให้ ต้องตั้งรหัสชั่วคราว อย่างน้อย 8 ตัวอักษร (ห้ามตรงกับชื่อผู้ใช้ ห้ามเดาง่าย เช่น 12345678/password) — และผู้ใช้จะถูกบังคับตั้งรหัสใหม่อีกครั้งตอนล็อกอินครั้งถัดไป

ข้อความ สาเหตุ
ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง ชื่อผู้ใช้หรือรหัสผ่านผิด (ระบบไม่ระบุว่าผิดตรงไหนเพื่อความปลอดภัย)
บัญชีนี้ถูกปิดการใช้งาน บัญชีถูกระงับระหว่างใช้งานอยู่ — ผู้ใช้จะถูกพากลับไปหน้าเข้าสู่ระบบทันทีที่กดใช้งานหน้าถัดไป (ที่หน้าเข้าสู่ระบบจะไม่ขึ้นข้อความนี้ บัญชีที่ถูกปิดจะได้ "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" เหมือนกรอกรหัสผิด เพื่อไม่ให้คนภายนอกเดาได้ว่ามีบัญชีนี้อยู่จริง) ตรวจสาเหตุจริงได้ที่ "ประวัติการใช้งาน"
มีการพยายามเข้าสู่ระบบหลายครั้งจากเครือข่ายนี้ พยายามเข้าสู่ระบบถี่เกินไป ระบบมีเพดาน 2 ชั้น: (1) รายบัญชี — กรอกผิด 10 ครั้งของคู่ "ชื่อผู้ใช้ + เครือข่ายเดียวกัน" ภายใน 15 นาที จะถูกบล็อก (ชั้นนี้เข้มกว่าและมักชนก่อน) และ (2) รายเครือข่าย — 20 ครั้ง/15 นาที ต่อหนึ่งเครือข่าย (IP) รอประมาณ 15 นาทีแล้วลองใหม่ ใต้ข้อความจะมีคำอธิบายว่า "ระบบระงับชั่วคราวเพื่อความปลอดภัย กรุณาลองใหม่อีกประมาณ 15 นาที บัญชีของคุณไม่ได้ถูกปิดใช้งานถาวร" — ไม่ใช่การปิดบัญชีถาวร และเมื่อเข้าสู่ระบบสำเร็จ ตัวนับรายบัญชีจะถูกล้างทันที

งานที่ 2 — ดูศูนย์ควบคุมระบบ (หน้าแรก)

ใช้เมื่อ: เริ่มงานแต่ละวัน เพื่อดูภาพรวมและการเตือนสำคัญ

ขั้นตอน:

  1. หลังเข้าสู่ระบบ ระบบเปิดหน้า "ศูนย์ควบคุมระบบ" ให้อัตโนมัติ
  2. ดูแถบ "สถานะการเดินรถวันนี้" (แถบแรกของหน้า): ช่อง ส่งเช้า และ รับเย็น บอกจำนวนที่เช็กแล้ว/ทั้งหมด พร้อมแถบความคืบหน้าและคำสถานะ (ยังไม่เริ่มรอบ / กำลังดำเนินการ / ต้องติดตาม / ล่าช้า / ครบแล้ว) และช่อง เหตุฉุกเฉินวันนี้ บอกจำนวนเหตุ พร้อมคำว่า "ไม่มีเหตุ" หรือ "ต้องตรวจสอบ"
    • รอบที่ยังไม่มีใครถูกเช็กจะขึ้นเลข 0 ขีด "—" และคำว่า "ยังไม่เริ่มรอบ" — เป็นเรื่องปกติ เช่น ช่วงเช้ารอบ "รับเย็น" ยังไม่เริ่ม ไม่ใช่ความผิดพลาด
  3. ตรวจแถบ "สิ่งที่ต้องดำเนินการ" — ระบบเฝ้าให้ 3 เรื่อง และขึ้นเป็นการ์ดใหญ่เฉพาะเรื่องที่มีงานค้าง:
    • "ผู้ใช้ต้องดูแล" → กดที่การ์ด (หรือ "ดูทั้งหมด →") ไปหน้า "จัดการผู้ใช้งาน" แบบกรองเฉพาะบัญชีที่ถูกระงับ
    • "คำขอรออนุมัติ" → แสดงจำนวนคำขอที่รอเท่านั้น กดเข้าไม่ได้ (ยังไม่มีหน้ารวมของผู้ดูแลระบบ)
    • "ลบข้อมูล (24 ชม.)" → กดไปหน้า "ประวัติการใช้งาน" แบบกรองเฉพาะการลบ (ระบบนับตามวันที่ประเทศไทย ตั้งแต่เมื่อวานถึงวันนี้)
    • เรื่องที่ไม่มีงานค้างจะยุบเหลือบรรทัดเดียวว่า "เรียบร้อย · …" ส่วนเรื่องที่โหลดข้อมูลไม่สำเร็จจะขึ้นบรรทัด "ไม่ทราบสถานะ · …" (ไม่ถือว่าเรียบร้อย ให้กดรีเฟรชแล้วดูใหม่)
  4. ดูแถบ "ข้อมูลระบบ" — ตัวเลขรวม 4 ช่อง: รถรับส่ง / นักเรียน / โรงเรียน / ผู้ใช้งานทั้งหมด (ช่องสุดท้ายจะมีบรรทัดรอง "ระงับอยู่ … บัญชี" เมื่อมีบัญชีที่ถูกระงับอยู่)
  5. ใช้แถบ "ทางลัดบริหาร" ไปงานที่ใช้บ่อย: จัดการผู้ใช้งาน / ประวัติการใช้งาน / จัดการโรงเรียน / ตรวจสภาพรถ
  6. หัวหน้าจอบอกเวลาที่ดึงข้อมูลว่า "ข้อมูล ณ …" และมีปุ่ม "รีเฟรช" ที่มุมขวาบน ถ้าโหลดข้อมูลบางส่วนไม่สำเร็จจะขึ้นแถบแดง "โหลดข้อมูลบางส่วนไม่สำเร็จ" — ตัวเลขอาจไม่ครบ ให้กดรีเฟรชอีกครั้ง

ภาพ: ศูนย์ควบคุมระบบ

✅ ผลลัพธ์ที่ถูกต้อง: เห็นแถบ "สถานะการเดินรถวันนี้", "สิ่งที่ต้องดำเนินการ" (การ์ดเฉพาะเรื่องที่มีงานค้าง หรือบรรทัด "เรียบร้อย" เมื่อไม่มีงานค้าง), "ข้อมูลระบบ" และ "ทางลัดบริหาร" ครบ พร้อมเวลา "ข้อมูล ณ …" ที่หัวหน้าจอ

ℹ️ การ์ด "คำขอรออนุมัติ" แสดงตัวเลขรวมเพื่อเตือนเท่านั้น ยังไม่มีหน้าคำขอรายชื่อรวมของ admin — การอนุมัติคำขอเปลี่ยนรายชื่อ (roster) ทำที่ฝั่งโรงเรียน

งานที่ 3 — จัดการผู้ใช้งาน (สร้าง/แก้ไข/รีเซ็ต/ลบ)

ใช้เมื่อ: ต้องสร้างหรือดูแลบัญชีทุกบทบาท (สิทธิ์เฉพาะ admin)

ภาพ: จัดการผู้ใช้งาน

สิ่งที่เห็นบนหน้าจอ: ปุ่ม "+ สร้างผู้ใช้ใหม่", ช่องค้นหา "ค้นหาชื่อผู้ใช้…", ตัวกรอง "ทุกบทบาท", ตารางผู้ใช้ (ชื่อผู้ใช้ / ชื่อแสดง / บทบาท / หน่วยงาน / ระดับชั้น / สถานะ / จัดการ) แต่ละแถวมีปุ่ม "แก้ไข" "รีเซ็ตรหัส" "ลบ" — ป้ายสถานะ: ระงับ (แดง) / รอเปลี่ยนรหัส (เหลือง) / ใช้งาน (เขียว)

ขั้นตอน — สร้างผู้ใช้ใหม่:

  1. กด "+ สร้างผู้ใช้ใหม่"
  2. กรอก ชื่อผู้ใช้ และ รหัสผ่าน (ชั่วคราว) — อย่างน้อย 8 ตัวอักษร (ไม่เกิน 128), ห้ามตรงกับชื่อผู้ใช้, ห้ามเดาง่าย (เช่น 12345678, password), ห้ามใช้อักขระตัวเดียวซ้ำทั้งหมด
  3. เลือก บทบาท — คนขับ / โรงเรียน / สังกัด / จังหวัด / ขนส่ง / ผู้ดูแลระบบ
  4. ถ้าบทบาทเป็น โรงเรียน / สังกัด / จังหวัด เลือก "หน่วยงาน" (scope) ให้ถูกต้อง
  5. ถ้าบทบาท โรงเรียน เลือก "ระดับชั้น" ได้ (= สร้างบัญชีครูประจำสายชั้น แบบอ่านอย่างเดียวเฉพาะชั้นนั้น)
  6. กด "สร้างผู้ใช้"

ขั้นตอน — แก้ไขผู้ใช้:

  1. กด "แก้ไข" ที่แถวของผู้ใช้
  2. ปรับได้ 2 อย่าง: ชื่อแสดง และ สถานะ (ใช้งาน ↔ ระงับ)
  3. กด "บันทึก"

ขั้นตอน — รีเซ็ตรหัสผ่าน:

  1. กด "รีเซ็ตรหัส" ที่แถวของผู้ใช้
  2. กรอกรหัสใหม่ (ชั่วคราว) อย่างน้อย 8 ตัวอักษร (ห้ามตรงกับชื่อผู้ใช้ ห้ามเดาง่าย)
  3. ยืนยัน → ระบบแสดง "รีเซ็ตรหัสผ่านสำเร็จ — ผู้ใช้จะต้องเปลี่ยนรหัสผ่านเมื่อ login ครั้งถัดไป"

⚠️ ข้อความบนหน้าจอยังเขียนว่า "6 ตัวอักษร" — ให้ยึด 8 ตัวอักษรเสมอ ช่องรหัสผ่านตอนสร้างผู้ใช้มีข้อความช่วยว่า "อย่างน้อย 6 ตัวอักษร" และช่องตอนรีเซ็ตใช้ชื่อช่องว่า "รหัสผ่านใหม่ (อย่างน้อย 6 ตัว)" แต่ระบบจริงบังคับ อย่างน้อย 8 ตัวอักษร ถ้าตั้ง 6–7 ตัวจะถูกปฏิเสธด้วยข้อความ "รหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร" (เฉพาะช่องรีเซ็ต ถ้าสั้นกว่า 6 ตัว หน้าจอจะเตือนว่า "รหัสผ่านต้องมีอย่างน้อย 6 ตัวอักษร" ขึ้นมาก่อน) — ไม่ใช่ความผิดพลาดของผู้ใช้ เป็นข้อความบนหน้าจอที่ยังไม่ได้แก้ ตั้งรหัสชั่วคราว 8 ตัวขึ้นไปทุกครั้งแล้วจะไม่เจอปัญหานี้

ขั้นตอน — ลบผู้ใช้:

  1. กด "ลบ" ที่แถวของผู้ใช้ → ระบบเปิดกล่องยืนยัน "ลบผู้ใช้ออกจากระบบ?" ซึ่งแสดงชื่อผู้ใช้ (และชื่อแสดง ถ้ามี) พร้อมข้อความ "บัญชีนี้จะเข้าใช้งานระบบไม่ได้อีก การกระทำนี้ถูกบันทึกใน audit log" → ตรวจว่าเป็นบัญชีที่ต้องการจริง แล้วกด "ลบผู้ใช้" (ถ้าไม่ใช่ ให้กด "ยกเลิก" — ระบบวางเคอร์เซอร์ไว้ที่ปุ่มนี้ก่อนเสมอ เพื่อกันเผลอกดลบ)
  2. ระบบลบแบบ soft delete (ซ่อนจากระบบแต่ยังเก็บประวัติ)

✅ ผลลัพธ์ที่ถูกต้อง: บัญชีใหม่ถูกตั้งเป็น "ต้องเปลี่ยนรหัส" เสมอ / การแก้ไข-รีเซ็ต-ลบ มีผลในตารางทันที

⚠️ ถ้าติดปัญหา:

  • ชื่อผู้ใช้ซ้ำ → ขึ้น "ชื่อผู้ใช้นี้มีอยู่ในระบบแล้ว" ให้เลือกชื่อใหม่
  • หน้าจอแก้ไข ไม่มีช่องเปลี่ยนบทบาท/หน่วยงาน — ถ้าต้องเปลี่ยน แนะนำให้สร้างบัญชีใหม่ให้ถูกบทบาทแล้วปิดบัญชีเดิม
  • เปิดใช้งานบัญชีคนขับซ้ำอาจถูกบล็อก → ขึ้น "ไม่สามารถเปิดใช้งานบัญชีคนขับนี้ได้…" (บัญชีซ้ำ/ผูกรถที่ถูกปิด) ให้ใช้บัญชีหลัก (canonical) หรือใช้ wizard ที่ "สุขภาพข้อมูลคนขับ" (งานที่ 6)
  • รีเซ็ตรหัสจะทำให้ session เดิมของผู้ใช้คนนั้นหมดอายุทันที (ต้องเข้าสู่ระบบใหม่)
  • ลบบัญชีตัวเองไม่ได้ → ขึ้น "ไม่สามารถลบตัวเองได้"

งานที่ 4 — อนุมัติคำขอโอนย้ายนักเรียน

ใช้เมื่อ: มีคำขอย้าย/แก้โรงเรียนที่ผิด — ไม่มีอะไรถูกย้ายจนกว่าคุณจะกดอนุมัติ

ภาพ: คำขอโอนย้ายนักเรียน

ขั้นตอน:

  1. เลือกตัวกรอง: รออนุมัติ / โอนย้ายแล้ว / ไม่อนุมัติ / ทั้งหมด
  2. กด "เปิดดู" ที่คำขอ — อ่านรายละเอียดและคำเตือน (เช่น รหัสนักเรียนซ้ำที่ปลายทาง หรือนักเรียนยังมีรถผูกอยู่)
  3. ใส่ "หมายเหตุผู้ดูแล" (จำเป็น — หมายเหตุนี้จะถูกบันทึกไว้กับคำขอและใน audit log)
  4. กด "อนุมัติและดำเนินการโอนย้าย" หรือ "ไม่อนุมัติคำขอ"

✅ ผลลัพธ์ที่ถูกต้อง: เมื่ออนุมัติ ระบบปิดข้อมูลนักเรียนเดิม (soft delete + ตัดรถ) แล้วสร้างนักเรียนใหม่ที่โรงเรียนปลายทาง (รหัสใหม่อัตโนมัติ, คัดลอกการผูกผู้ปกครอง, ไม่ผูกรถ) ในขั้นตอนเดียว — กดอนุมัติซ้ำปลอดภัย (ระบบจะแจ้งว่าดำเนินการไปแล้ว)

⚠️ ถ้าติดปัญหา:

  • ป้ายสถานะ "ไม่สำเร็จ" (ค่าในระบบ: FAILED) = พบรหัสนักเรียนซ้ำที่โรงเรียนปลายทาง หรือข้อมูลไม่ครบ — แก้ที่ปลายทางก่อนแล้วให้โรงเรียนส่งคำขอใหม่
  • ป้ายสถานะ "ต้องตรวจสอบใหม่" (ค่าในระบบ: STALE_NEEDS_REVIEW) = ข้อมูลนักเรียนเปลี่ยนไปหลังส่งคำขอ ต้องเปิดดูและตรวจใหม่ก่อนอนุมัติ
  • ป้ายสถานะ "ยกเลิกแล้ว" = โรงเรียนต้นทางถอนคำขอเอง ผู้ดูแลระบบไม่ต้องดำเนินการใด ๆ
  • กดปุ่มแล้วเหมือนยังไม่มีอะไรเกิดขึ้น — เป็นเรื่องปกติ ปุ่ม "อนุมัติและดำเนินการโอนย้าย" และ "ไม่อนุมัติคำขอ" มี 2 จังหวะ: กดครั้งแรกระบบจะเปิดช่อง "หมายเหตุผู้ดูแล" (จำเป็น) แล้วต้องกดปุ่มยืนยันอีกครั้ง ("ยืนยันอนุมัติและโอนย้าย" / "ยืนยันไม่อนุมัติ") ระบบจึงจะทำงานจริง — ถ้ายังไม่กรอกหมายเหตุ ปุ่มยืนยันจะเป็นสีจางกดไม่ได้ และกด "กลับ" เพื่อย้อนไปเลือกใหม่ได้

งานที่ 5 — อนุมัติคำขอเกี่ยวกับรถ

ใช้เมื่อ: มีคำขอ "ขอกู้คืนรถ / ขอใช้รถที่มีอยู่ / ขอเพิ่มรถ / ขอตรวจสอบ"

ภาพ: คำขอเกี่ยวกับรถ

ขั้นตอน:

  1. เลือกตัวกรอง: รออนุมัติ / สำเร็จแล้ว / ไม่อนุมัติ / ทั้งหมด (หน้านี้ใช้คำว่า "สำเร็จแล้ว" ส่วนหน้าคำขอโอนย้ายใช้คำว่า "โอนย้ายแล้ว")
  2. กด "เปิดดู" เพื่อดูรายละเอียด
  3. ใส่ หมายเหตุผู้ดูแล (จำเป็น)
  4. กด "อนุมัติและกู้คืนรถ" / "อนุมัติคำขอ" หรือ "ไม่อนุมัติ"

✅ ผลลัพธ์ที่ถูกต้อง: มีเพียงคำขอ กู้คืนรถ เท่านั้นที่แก้ข้อมูลรถจริง (นำรถที่ถูกลบกลับมาใช้) — คำขอประเภทอื่นเป็นเพียงข้อมูลแจ้งให้ทราบ ไม่แตะข้อมูลรถ

⚠️ ถ้าติดปัญหา: ถ้ามีรถ ทะเบียนเดียวกันที่ยังใช้งานอยู่ ปุ่มอนุมัติจะถูกปิด (disable) และการกู้คืนจะ FAILED พร้อมข้อความ "ไม่สามารถกู้คืนรถได้ เนื่องจากมีรถทะเบียนเดียวกันที่ใช้งานอยู่แล้ว" — ต้องจัดการรถที่ทะเบียนชนกันก่อน

งานที่ 6 — ดูแลสุขภาพข้อมูลคนขับ + wizard

ใช้เมื่อ: ตรวจความถูกต้องข้อมูลคนขับ หรือต้องกู้คืน/ย้าย/ปิดคนขับ

ภาพ: สุขภาพข้อมูลคนขับ

สิ่งที่เห็นบนหน้าจอ: การ์ดสรุป 7 รายการ — "รถที่ยังไม่มีคนขับ" / "คนขับที่ยังไม่มีรถ" / "บัญชีซ้ำ/ถูกปิดใช้งาน" / "คนขับยังไม่ผูกโปรไฟล์" / "งานชี้รถที่ถูกปิดใช้งาน" / "รถมีคนขับซ้ำ" / "บล็อกการเปิดใช้งานซ้ำ (30 วัน)", รายการ "รถที่ยังไม่มีคนขับ" (เฉพาะเมื่อมีรถค้าง), และปุ่ม "เครื่องมือจัดการคนขับ" ที่เปิด wizard

ขั้นตอน — ใช้ wizard เครื่องมือจัดการคนขับ:

  1. กด "เครื่องมือจัดการคนขับ" เปิด wizard
  2. เลือก action: กู้คืนบัญชีคนขับ / ย้ายคนขับไปรถใหม่ / ปิดใช้งานคนขับ
  3. กรอก "รหัสผู้ใช้คนขับ" (ใต้ช่องเขียนว่า "user id ในระบบ") — ถ้าเลือก ย้ายคนขับไปรถใหม่ จะมีช่อง "รถปลายทาง" (ใต้ช่องเขียนว่า "vehicle id") เพิ่มขึ้นมาให้กรอกด้วย ทั้งสองช่องมีเครื่องหมาย * คือจำเป็นต้องกรอก
  4. กด "ตรวจสอบก่อนดำเนินการ" — ระบบแสดงผลตรวจล่วงหน้า (preflight): อนุญาต / ถูกบล็อก / คำเตือน
  5. ถ้าผ่าน ใส่ "เหตุผล" (จำเป็น — บันทึกลงประวัติการเปลี่ยนแปลง) แล้วกด "ยืนยันดำเนินการ"

✅ ผลลัพธ์ที่ถูกต้อง: preflight แสดงผลล่วงหน้า; ปิดใช้งานคนขับ จะปิดบัญชีและจบงานมอบหมายที่ active ให้ในขั้นตอนเดียว

⚠️ ถ้าติดปัญหา:

  • กู้คืน: ถ้าเป็นบัญชีคนขับซ้ำจะถูกบล็อก — ต้องใช้บัญชีหลัก (canonical); กรณีไม่มีรถ active เป็นเพียงคำเตือน ดำเนินการต่อได้
  • ย้ายคนขับ: ถ้ารถปลายทางมีคนขับอยู่แล้ว หลังกด "ตรวจสอบก่อนดำเนินการ" ระบบจะขึ้นคำเตือนพร้อมช่องติ๊ก "ยืนยันสิ้นสุดงานคนขับเดิมของรถคันนี้" ต้องติ๊กช่องนี้ก่อนกด "ยืนยันดำเนินการ" (กันคนขับซ้ำในรถคันเดียว) ถ้าไม่ติ๊ก ระบบจะยังไม่ย้ายให้ และขึ้นข้อความ "รถคันนี้มีคนขับที่ใช้งานอยู่แล้ว กรุณายืนยันการสิ้นสุดงานเดิม" — ให้เปิดเครื่องมือใหม่ ตรวจสอบอีกครั้ง แล้วติ๊กช่องนี้

งานที่ 7 — ตรวจสอบจุดรับส่ง

ใช้เมื่อ: จัดการกรณีพิเศษของจุดรับส่งทั้งระบบ (การเพิ่มจุดหลักทำผ่านบัญชีคนขับ/โรงเรียน)

ภาพ: ตรวจสอบจุดรับ-ส่ง

ขั้นตอน:

  1. กด "เพิ่มกรณีพิเศษ" เพื่อเพิ่มจุดรับส่งกรณีพิเศษ (override)
  2. กรองตามรถเพื่อหารายการที่ต้องการ
  3. (ถ้าลบหลายรายการ) เลือกหลายรายการแล้วกด "ลบรายการที่เลือก"
  4. ใช้ปุ่มแถวตามต้องการในคอลัมน์ "จัดการ": "นักเรียน" (จัดการนักเรียนที่ผูกกับจุดนี้) / "แก้ไข" / "ลบ" — ตารางมีคอลัมน์ ทะเบียนรถ / ป้ายชื่อ / รอบ / นักเรียน / พิกัด / จัดการ

✅ ผลลัพธ์ที่ถูกต้อง: จุดกรณีพิเศษถูกบันทึก; การลบเป็น soft delete (ข้อมูลซ่อนแต่ยังอยู่ใน audit log)

⚠️ ถ้าติดปัญหา: ป้ายชื่อจุดต้องไม่เกิน 100 ตัวอักษร, พิกัดต้องอยู่ในช่วงที่ถูกต้อง, นักเรียนที่ผูกต้องเป็นของรถคันนั้นและไม่มีจุดซ้ำในรอบเดียวกัน

งานที่ 8 — ตรวจสอบตำแหน่งรถ (GPS)

ใช้เมื่อ: ดูสถานะ GPS ของรถทั้งระบบ (อ่านอย่างเดียว — ไม่มีปุ่มแก้ไข)

ภาพ: ตรวจสอบตำแหน่งรถ (live)

ขั้นตอน:

  1. เปิดเมนู "ตรวจสอบตำแหน่งรถ"
  2. ดูตัวเลขสรุปทั้งหมด 10 ช่อง: รถทั้งหมด / นักเรียนที่เกี่ยวข้อง / ออนไลน์ / สัญญาณเก่า / หยุดส่ง · ช่อง "ออฟไลน์ / ยังไม่มีข้อมูล" (นับเป็นช่องเดียว) · และอีก 4 ช่อง กำลังมีพิกัดจริง / ยังไม่เคยส่งตำแหน่ง / ความแม่นยำต่ำ / ไม่อัปเดตเกิน 5 นาที
  3. ใช้ช่องค้นหา "ค้นหาทะเบียน หรือชื่อคนขับ…" (ค้นได้ทั้งทะเบียนรถและชื่อคนขับ) และตัวกรอง ทั้งหมด / กำลังมีพิกัดจริง / ยังไม่เคยส่งตำแหน่ง / ไม่อัปเดตเกิน 5 นาที / ความแม่นยำต่ำ เพื่อจำกัดรายการรถที่แสดง — ตัวเลขสรุปด้านบนยังนับรถทั้งหมดเสมอ ไม่เปลี่ยนตามตัวกรอง
  4. ดูแผนที่และรายการรถ (หน้านี้รีเฟรชอัตโนมัติทุก 15 วินาที)

✅ ผลลัพธ์ที่ถูกต้อง: เห็นตัวเลขสรุป + แผนที่ + รายการรถ และข้อมูลอัปเดตเองทุก 15 วินาที

ℹ️ แบนเนอร์ระบุ "ทุกการเปิดดูจะถูกบันทึกใน audit log" — การเข้าดูหน้านี้ถูกบันทึกเพื่อความโปร่งใส

งานที่ 9 — ดูความพร้อมเปิดใช้งาน

ใช้เมื่อ: ตรวจว่าข้อมูลพร้อมเปิดบังคับใช้นโยบายความปลอดภัยแค่ไหน (รายงานรวม ไม่มีข้อมูลส่วนบุคคล)

ภาพ: ความพร้อมเปิดใช้งาน

ขั้นตอน:

  1. เปิดเมนู "ความพร้อมเปิดใช้งาน"
  2. ดูสถานะรถ (พร้อมใช้งาน / ต้องเติมข้อมูล / มีข้อมูลเสี่ยง / ถูกระงับ)
  3. ดูสถานะคนขับ (การผูกบัญชี/ใบอนุญาต) และการมอบหมายคนขับ + คนขับสำรอง
  4. ดูรายการ "ช่องว่าง (gaps)" พร้อมเจ้าของงานที่ต้องแก้ แล้วประสานให้แก้ไข

✅ ผลลัพธ์ที่ถูกต้อง: เห็นภาพรวมความพร้อมและรายการ gaps พร้อมเจ้าของงาน

ℹ️ โหมดความปลอดภัย แสดงอยู่ที่หัวหน้าจอนี้ว่า "โหมดความปลอดภัย: สังเกตการณ์ (OBSERVE)" หรือ "โหมดความปลอดภัย: บังคับใช้ (ENFORCE)" — ให้ดูค่าจริงจากหน้าจอเสมอ ค่าตั้งต้นของระบบคือ สังเกตการณ์ (OBSERVE) คือเฝ้าสังเกต ยังไม่บล็อกรถหรือคนขับ ส่วนการเปลี่ยนเป็น บังคับใช้ (ENFORCE) ต้องตั้งค่าที่เซิร์ฟเวอร์โดยผู้ดูแลเซิร์ฟเวอร์เท่านั้น สลับจากหน้าจอนี้ไม่ได้ และระบบจะไม่เปลี่ยนโหมดเองเมื่อถึงวันที่ที่กำหนดไว้

งานที่ 10 — ดูสุขภาพระบบ

ใช้เมื่อ: ดูสถิติการใช้งานระบบย้อนหลัง 30 วัน

ภาพ: สุขภาพระบบ — ภาพนี้ถ่ายตอนข้อมูลตัวอย่างยังโหลดไม่ขึ้น ตัวเลขจึงว่างและมีคำว่า "undefined" บนระบบจริงจะมีตัวเลขครบทุกใบ

ขั้นตอน:

  1. เปิดเมนู "สุขภาพระบบ"
  2. ดูตัวเลขสรุป 5 ใบบนสุด: "ผู้ใช้ active (30 วัน)" (มีบรรทัดรองบอกจำนวนผู้ใช้ทั้งหมด) / "เข้าสู่ระบบ (30 วัน)" / "ล็อกอินล้มเหลว" / "รีเซ็ตรหัสผ่าน" (เดือนนี้) / "Actions ทั้งหมด" (30 วัน) แล้วดูส่วน "การเข้าชมเว็บไซต์" — วันนี้ / 7 วันล่าสุด / 30 วันล่าสุด
  3. ดู "Top 5 ฟีเจอร์ที่ใช้บ่อย" / "Bottom 5 ฟีเจอร์ที่ใช้น้อย", "การใช้งานแยกตามประเภท" (แยกตามประเภทการกระทำ เช่น สร้าง / แก้ไข / ลบ / ส่งออก), "กิจกรรมแยกตามสิทธิ์" (แยกตามบทบาทผู้ใช้ ชื่อบทบาทแสดงเป็นภาษาอังกฤษ เช่น admin, school, driver) และ "กิจกรรมรายวัน (14 วัน)"
  4. กด "รีเฟรช" เพื่ออัปเดตตัวเลข

✅ ผลลัพธ์ที่ถูกต้อง: เห็นสถิติการใช้งานครบทุกส่วน

ℹ️ ตัวเลข "Error count" เป็นค่าประมาณจากการ login ล้มเหลวเท่านั้น (ระบบยังไม่มีบันทึก error แบบถาวร) — ใช้ดูแนวโน้มคร่าว ๆ ไม่ใช่ตัวเลขแม่นยำ

งานที่ 11 — ดูประวัติการใช้งาน (Audit Log) + ส่งออก

ใช้เมื่อ: ตรวจสอบ/ตามรอยการกระทำในระบบ — หน้า "ประวัติการใช้งานระบบ (ทั้งหมด)" แสดง audit log ทั้งระบบโดยไม่จำกัดขอบเขต

ภาพ: ประวัติการใช้งานระบบ (Audit log)

ขั้นตอน:

  1. ใช้ตัวกรองด้านบนของหน้า: ช่องเลือกประเภทการกระทำ (ปกติแสดง "ทุกการกระทำ" เลือกได้เป็น สร้าง / แก้ไข / ลบ / นำเข้า / อนุมัติ / ส่งออก / เข้าสู่ระบบ) และช่องวันที่ "ตั้งแต่" กับ "ถึง" เพื่อจำกัดช่วงวันที่
  2. เลื่อนดูรายการ (แสดงเป็นการ์ดทีละรายการ เรียงจากล่าสุดไปเก่าสุด หน้าละ 30 รายการ) เปลี่ยนหน้าด้วยปุ่ม "ก่อนหน้า" / "ถัดไป" หรือพิมพ์เลขหน้าในช่อง "หน้า" แล้วกด Enter
  3. กดปุ่ม "Export CSV" ที่มุมขวาบนของหน้า เพื่อดาวน์โหลดตามตัวกรองที่เลือกอยู่

✅ ผลลัพธ์ที่ถูกต้อง: เห็นรายการ audit ตามตัวกรอง / CSV มี BOM (เปิดในภาษาไทยได้)

⚠️ ถ้าติดปัญหา:

  • ข้อมูลส่วนบุคคล (เบอร์โทร / LINE id / ความลับ) จะถูก ปกปิด (redact) ก่อนแสดงและก่อนส่งออกเสมอ (เป็นพฤติกรรมปกติ)
  • CSV จำกัดสูงสุด 5,000 แถว — ถ้าเกินจะมีหมายเหตุระบุว่าถูกตัด

งานที่ 12 — งานวิจัย / ประเมินผล

ใช้เมื่อ: สร้าง baseline, ส่งออกข้อมูลวิจัย, ประเมินผลแยกบทบาท, ทำสรุปผู้บริหาร (เฉพาะ admin)

12.1 กรอบวัดผลระบบ — คู่มือตัวชี้วัด เกณฑ์ การปรับระบบ และข้อพึงระวัง แยกตามบทบาท (เอกสารอ้างอิง ไม่มีปุ่มสั่งงาน)

ภาพ: กรอบวัดผลระบบ

12.2 เปรียบเทียบ Baseline — เทียบ baseline กับปัจจุบัน 8 ตัวชี้วัด ขั้นตอน: ถ้ามี baseline อยู่แล้ว ให้เลือก "Baseline อ้างอิง" ที่จะใช้เทียบก่อน (ถ้ายังไม่มี หน้าจะขึ้นกล่องเตือน "ยังไม่มี baseline" แทนช่องเลือก) แล้วกด "Snapshot วันนี้", "สร้าง Baseline" หรือ "Baseline (Pre-measure)" ตามต้องการ — ปุ่มสุดท้ายจะเปิดกล่อง "บันทึก Baseline (Pre-measure)" ให้กด "ยืนยันบันทึก Baseline" ยืนยันอีกครั้ง ⚠️ ถ้าติดปัญหา: สร้าง Baseline ซ้ำภายใน 24 ชั่วโมงไม่ได้ (กัน baseline ซ้อนกัน) — รอครบ 24 ชั่วโมงหรือใช้ baseline ที่มีอยู่

ภาพ: เปรียบเทียบ Baseline

12.3 ส่งออกข้อมูลวิจัย ขั้นตอน:

  1. เลือกช่วงวันที่ + ชุดข้อมูล (Snapshots / Action Logs / Export Evidence / Summary)
  2. ดูกล่อง "ตัวอย่างข้อมูลที่จะส่งออก" — จำนวน Snapshots / Audit Logs / Export Logs และช่วงวันที่ของข้อมูล
  3. อ่านแถบสถานะใต้กล่องตัวอย่างก่อนกดดาวน์โหลดทุกครั้ง แถบนี้บอกว่า Snapshot ล่าสุด เป็นวันที่เท่าไร อายุกี่วัน และเกินเกณฑ์หรือไม่
  4. ถ้าแถบขึ้นว่า "ชุดข้อมูลนี้ยังใช้อ้างผลวิจัยไม่ได้" จะมีบรรทัด "เหตุผล:" ต่อท้าย (เช่น ยังไม่ freeze research protocol, ยังไม่มี baseline snapshot, snapshot ล่าสุดเก่าเกินเกณฑ์) กรณีนี้ยังส่งออกไฟล์ได้ตามปกติ แต่ยังนำตัวเลขไปอ้างเป็นผลวิจัยไม่ได้ จนกว่าแถบจะขึ้นว่า "ชุดข้อมูลนี้อยู่ในช่วง protocol ที่ freeze แล้ว"
  5. ดาวน์โหลดเป็น JSON / CSV / Excel ✅ ผลลัพธ์ที่ถูกต้อง: ข้อมูลส่งออกตัด IP/User Agent/ค่าก่อนแก้ไขออก และปกปิดข้อมูลส่วนบุคคลในค่าหลังแก้ไข เพื่อความเป็นส่วนตัว

ภาพ: ส่งออกข้อมูลวิจัย — ภาพนี้ถ่ายจากข้อมูลตัวอย่างที่ยังไม่ขึ้นแถบสถานะความพร้อมของหลักฐานใต้กล่อง "ตัวอย่างข้อมูลที่จะส่งออก" บนระบบจริงจะมีแถบนี้เสมอ

12.4 ประเมินผลแยก Role — เปิดเมนู "ประเมินผลแยก Role" จะได้หน้า "แดชบอร์ดประเมินผลแยกตามสิทธิ์" ซึ่งแสดงการ์ดของทั้ง 6 บทบาท (คนขับ / โรงเรียน / สังกัด / จังหวัด / ขนส่ง / แอดมิน) แต่ละการ์ดมีสถานะหลักฐาน 3 ระดับ คือ "มีหลักฐานระบบเบื้องต้น" / "มีหลักฐานบางส่วน" / "ยังไม่มีหลักฐานพอ" (ถ้าระบบยังไม่ส่งค่าสถานะของบทบาทนั้นมา จะขึ้นว่า "ยังไม่ทราบสถานะหลักฐาน") กดที่การ์ดเพื่อกางดูตัวชี้วัดของบทบาทนั้นเทียบกับ baseline

⚠️ ระบบไม่มีสถานะที่แปลว่า "พร้อมประเมินผลวิจัยแล้ว" — ระดับสูงสุดที่ข้อมูลในระบบให้ได้คือ "มีหลักฐานระบบเบื้องต้น" เท่านั้น หน้านี้จึงขึ้นแถบข้อความ "สถานะนี้เป็นความพร้อมของหลักฐาน ไม่ใช่ผลการวิจัย" ไว้ตลอด และย้ำว่า "จำนวน action ไม่ใช่เกณฑ์ความพร้อมประเมิน" ถ้ายังอ้างผลวิจัยไม่ได้ ระบบจะบอกเหตุผลไว้ในแถบเดียวกัน เช่น "ยังไม่ freeze research protocol" หรือ "ยังไม่มีการรับรองโดย Research lead" — ห้ามนำสถานะบนหน้านี้ไปอ้างเป็นผลการวิจัย

ภาพ: ประเมินผลแยก Role

12.5 สรุปผู้บริหาร — หน้า "สรุปภาพรวมการประเมินระบบ" รวมตัวเลข 6 ช่อง (หลักฐานระบบครบ / บางส่วน / ยังต้องเพิ่ม / ดีขึ้น / ลดลง / ต่ำ (<50%)), "สถานะความพร้อมรายสิทธิ์" ของ 6 บทบาท, "สิ่งที่ดีขึ้นจาก Baseline", กล่องจุดเสี่ยง และ "สิ่งที่ควรดำเนินการต่อ" ขั้นตอน: กด "พิมพ์รายงาน" (มุมขวาบนของแถบหัวเรื่องสีน้ำเงินเข้ม) เพื่อเปิดหน้าพิมพ์สำหรับผู้บริหาร จากนั้นกด "พิมพ์ / Save PDF" เพื่อสั่งพิมพ์หรือบันทึกเป็น PDF หรือกด "← กลับ" เพื่อย้อนกลับ (ปุ่มสองปุ่มนี้อยู่มุมขวาบนของหน้าจอ และจะไม่ติดไปในเอกสารที่พิมพ์)

⚠️ อ่านตัวเลขให้ถูก: ด้านบนของหน้ามีแถบเตือนถาวรว่า "สถานะนี้เป็นความพร้อมของหลักฐาน ไม่ใช่ผลการวิจัย" และ "จำนวน action ไม่ใช่เกณฑ์ความพร้อมประเมิน" — เมื่อข้อมูลยังไม่พอ ระบบจะเขียนตรง ๆ ว่า "ยังไม่มีข้อมูลพอเทียบกับ baseline (ตัวส่วนเป็น 0 หรือไม่มี snapshot) — ยังสรุปไม่ได้ว่าดีขึ้นหรือไม่" หัวข้อกล่องจุดเสี่ยงจะเปลี่ยนเป็น "ยังประเมินจุดเสี่ยงไม่ได้ (ข้อมูลไม่พอ)" และตัวชี้วัดที่เทียบไม่ได้จะถูกแยกไว้ในบรรทัด "ยังเทียบกับ baseline ไม่ได้ (ตัวส่วนเป็น 0 หรือไม่มีข้อมูล)" ส่วนในหน้าพิมพ์รายงาน ตารางตัวชี้วัดจะขึ้นคำว่า "ไม่มีข้อมูล" แทนตัวเลข 0% — ห้ามตีความว่า "ไม่มีข้อมูล" เท่ากับ "ไม่มีปัญหา"

ภาพ: หน้าพิมพ์รายงานสำหรับผู้บริหาร (เปิดจากปุ่ม "พิมพ์รายงาน") — ไม่ใช่หน้า "สรุปภาพรวมการประเมินระบบ" ที่อธิบายไว้ข้างต้น

งานที่ 13 — รายงานและการส่งออก

ใช้เมื่อ: ออกรายงานรายวัน/รายเดือน/สรุป — admin เห็นข้อมูลทั้งจังหวัด และส่งออกได้ทุกแบบ

ขั้นตอน:

  1. เปิดเมนู "รายงาน"
  2. เลือกประเภท: รายวัน / รายเดือน / สรุป (แสดงเป็นข้อมูล JSON บนหน้าจอ)
  3. ตั้งตัวกรองที่รองรับ: วันที่ (YYYY-MM-DD), เดือน (YYYY-MM), โรงเรียน, สังกัด, ทะเบียนรถ
  4. ส่งออกตามต้องการ: CSV (มี BOM เปิดภาษาไทยได้), Excel (.xlsx), PDF

การส่งออกอื่น ๆ ของ admin:

  • Audit CSV — ส่งออกประวัติการใช้งานทั้งระบบ (ปกปิดข้อมูลส่วนบุคคล สูงสุด 5,000 แถว) จากหน้า "ประวัติการใช้งาน" (งานที่ 11)
  • ชุดข้อมูลวิจัย — ส่งออก JSON/CSV/Excel จากหน้า "ส่งออกข้อมูลวิจัย" (งานที่ 12.3, เฉพาะ admin)

✅ ผลลัพธ์ที่ถูกต้อง: ได้ไฟล์รายงานตามรูปแบบที่เลือก / ทุกการส่งออกถูกบันทึกใน audit log (action = EXPORT) และใช้เป็น "หลักฐานการส่งออก (Export Evidence)" ในรายงานวิจัยได้

⚠️ ถ้าติดปัญหา: การส่งออกมีการจำกัดอัตรา (rate limit) ที่ 40 ครั้งต่อ 5 นาที — ถ้าส่งออกถี่เกินไปให้รอสักครู่

ภาพ: หน้ารายงาน — แท็บ รายวัน / รายเดือน / สรุปภาพรวม / เชิงนโยบาย พร้อมปุ่มส่งออก (ภาพนี้ถ่ายจากข้อมูลตัวอย่างที่ยังโหลดไม่ครบ ช่องจำนวนจึงขึ้นคำว่า "undefined" บนระบบจริงจะเป็นตัวเลข "ทำแล้ว/ทั้งหมด")

งานที่ 14 — เข้าใช้งานโมดูลบทบาทอื่น

ใช้เมื่อ: ต้องทำงานแทนบทบาทอื่น (admin เข้าได้เต็มสิทธิ์ทุกโมดูล)

ขั้นตอน:

  1. เลือกเมนูตามงาน:
    • จัดการโรงเรียน → โมดูลโรงเรียน (จัดการนักเรียน/นำเข้า)
    • เพิ่มโรงเรียนใหม่ → โมดูลสังกัด (จัดการบัญชีโรงเรียน/เพิ่มโรงเรียน)
    • ตรวจสภาพรถ → โมดูลขนส่ง (บันทึก/ดูผลตรวจสภาพ)
    • ภาพรวมจังหวัด → มุมมองระดับจังหวัด (ดูข้อมูลได้ทั้งจังหวัด) — เมนู ข้อมูลนักเรียน และ รถรับส่ง อยู่ในหมวด "ข้อมูลหลัก" เดียวกันนี้
    • หมายเหตุ: เมื่อเข้าโมดูลของโรงเรียน ("จัดการโรงเรียน") หรือของสังกัด ("เพิ่มโรงเรียนใหม่") จะมีแถบสีเหลืองอ่อนด้านบนให้เลือกขอบเขตก่อน คือ "Admin — เลือกโรงเรียน:" หรือ "Admin — เลือกสังกัด:" ถ้ายังไม่เลือก หน้าจอจะขึ้นว่า "กรุณาเลือกโรงเรียนก่อน" / "กรุณาเลือกสังกัดก่อน" และยังไม่แสดงข้อมูล
    • รายงาน → ดูงานที่ 13
  2. ใช้งานแต่ละโมดูลตามคู่มือของบทบาทนั้น ๆ

✅ ผลลัพธ์ที่ถูกต้อง: เข้าทำงานในโมดูลของบทบาทอื่นได้เต็มสิทธิ์

ภาพ: ศูนย์ควบคุมระบบของผู้ดูแลระบบ — ภาพชุดนี้ยังไม่ได้ถ่ายหน้าจอที่มีแถบ "Admin — เลือกโรงเรียน:" จะถ่ายเพิ่มในรอบถ่ายภาพครั้งถัดไป

งานที่ 15 — ฟีเจอร์ขั้นสูงที่ปิดอยู่ (อ้างอิง)

ใช้เมื่อ: มีคนถามถึงฟีเจอร์เหล่านี้ หรือเปิดเมนู/หน้าแล้วได้ 404

ℹ️ เมนู "จุดเตือนภัย (Geofences)" และ "การเบี่ยงเส้นทาง" จะถูก ซ่อนอัตโนมัติ เมื่อฟีเจอร์ยังไม่เปิด — ปัจจุบันคุณจะ ไม่เห็น 2 เมนูนี้ ส่วน "QR รถรับส่ง" มีอยู่ในระบบแต่ ไม่อยู่ในเมนู และปัจจุบันปิดอยู่

15.1 จุดเตือนภัย (Geofences)

⚠️ ฟีเจอร์นี้เปิดด้วย feature flag FEATURE_GEOFENCE — ปัจจุบันปิดอยู่ในการใช้งานจริง เมนูถูกซ่อนและการเปิดหน้าจะได้ผล 404 ต้องให้ผู้ดูแลเซิร์ฟเวอร์เปิด flag ก่อน

หน้านี้ (เมื่อเปิดใช้) จัดการ geofence (พื้นที่เสมือนรอบโรงเรียน/จุดรับส่ง): เพิ่ม/แก้ไข/ลบ, ปุ่ม "สร้างอัตโนมัติ" (สร้างชุดเริ่มต้น), ดูเหตุการณ์เข้า/ออกพื้นที่ 50 รายการล่าสุด — การตั้งค่าต้องระบุประเภทเป้าหมาย (โรงเรียน/จุดรับส่ง/อู่), เงื่อนไขทริกเกอร์ (เข้า/ออก/ทั้งสอง), พิกัด, รัศมี (1–50,000 เมตร), ผู้รับการแจ้งเตือน; การลบเป็น soft delete

15.2 การเบี่ยงเส้นทาง

⚠️ ฟีเจอร์นี้เปิดด้วย feature flag FEATURE_ROUTE_DEVIATION — ปัจจุบันปิดอยู่ในการใช้งานจริง เมนูถูกซ่อนและการเปิดหน้าจะได้ผล 404

หน้านี้ (เมื่อเปิดใช้) เป็น log แบบ อ่านอย่างเดียว ของเหตุการณ์รถเบี่ยงเส้นทาง/ล่าช้า/หยุดนิ่งนาน กรองได้ด้วย "เฉพาะที่ยังไม่ resolved" และระดับความรุนแรง (WARN / CRITICAL / INFO)

15.3 QR รถรับส่ง

⚠️ ฟีเจอร์นี้เปิดด้วย feature flag FEATURE_VEHICLE_QR — ปัจจุบันปิดอยู่ในการใช้งานจริง หน้านี้ ไม่มีในเมนู และการเรียก API จะได้ผล 404 ต้องให้ผู้ดูแลเซิร์ฟเวอร์เปิด flag ก่อน

หน้านี้ (เมื่อเปิดใช้) ใช้สร้าง/หมุน/ดู QR token ของรถ + พิมพ์ QR + ดูตัวอย่างข้อมูลระดับเจ้าหน้าที่

ℹ️ การดูข้อมูลระดับ 3 (ข้อมูลอ่อนไหว) ต้องเปิด flag เพิ่มอีกตัว (FEATURE_QR_LEVEL3) ซึ่งต้องผ่านการอนุมัติของผู้คุ้มครองข้อมูล (DPO) — ปิดเป็นค่าตั้งต้น

📷 ไม่มีภาพหน้าจอ — ฟีเจอร์ขั้นสูง (Geofence / การเบี่ยงเส้นทาง / QR) ถูกปิดด้วย feature flag ยังไม่เปิดใช้งานจริง จึงยังไม่มีหน้าจอให้แสดง

งานที่ 16 — ตั้งภาคเรียนปัจจุบัน

ใช้เมื่อ: ขึ้นภาคเรียนใหม่ หรือพบว่าการเช็กอิน/การนำเข้านักเรียนถูกบันทึกผิดเทอม (สิทธิ์เฉพาะ admin)

สิ่งที่เห็นบนหน้าจอ: หัวข้อ "ภาคเรียนปัจจุบัน", ปุ่ม "เพิ่มภาคเรียน" (มุมขวาบน) และรายการภาคเรียนทั้งหมด — ภาคเรียนที่ใช้อยู่มีป้าย "ปัจจุบัน" (เขียว) ส่วนแถวอื่นมีปุ่ม "ตั้งเป็นปัจจุบัน" ถ้ายังไม่เคยสร้างจะขึ้น "ยังไม่มีภาคเรียน"

ขั้นตอน — ตั้งภาคเรียนที่มีอยู่แล้วให้เป็นปัจจุบัน:

  1. เปิดเมนู "ภาคเรียนปัจจุบัน" ในหมวด "ตั้งค่าระบบ" ของแถบเมนูด้านข้าง
  2. กด "ตั้งเป็นปัจจุบัน" ที่แถวของภาคเรียนที่ต้องการ
  3. อ่านข้อความในกล่อง "ตั้งเป็นภาคเรียนปัจจุบัน?" แล้วกดยืนยัน "ตั้งเป็นปัจจุบัน"

ขั้นตอน — เพิ่มภาคเรียนใหม่:

  1. กด "เพิ่มภาคเรียน"
  2. กรอก "รหัสภาคเรียน" (ช่องเดียวที่บังคับ) รูปแบบ ปีการศึกษา-ภาคเรียน เช่น 2569-1 — ปีการศึกษาเป็นตัวเลข 4 หลัก และภาคเรียนเป็น 1, 2 หรือ 3 เท่านั้น
  3. ช่อง "ชื่อ", "วันเริ่ม" และ "วันสิ้นสุด" ไม่บังคับ — เว้นว่างได้ (กรอกไว้เพื่อให้อ่านง่ายขึ้นเท่านั้น)
  4. กด "บันทึก" (หรือ "ยกเลิก" เพื่อปิดฟอร์ม)
  5. ภาคเรียนที่เพิ่งเพิ่ม ยังไม่ใช่ภาคเรียนปัจจุบัน — ต้องกด "ตั้งเป็นปัจจุบัน" ที่แถวนั้นอีกครั้งตามขั้นตอนด้านบน

✅ ผลลัพธ์ที่ถูกต้อง: ระบบขึ้นข้อความ "ตั้งเป็นภาคเรียนปัจจุบันแล้ว" ป้าย "ปัจจุบัน" ย้ายมาที่ภาคเรียนที่เลือก และการเช็กอิน/การนำเข้านักเรียนหลังจากนี้จะถูกบันทึกในภาคเรียนนี้ — ข้อมูลของภาคเรียนก่อนหน้าจะไม่ถูกลบ และไม่ต้องรีสตาร์ทระบบ

⚠️ ถ้าติดปัญหา:

  • รหัสภาคเรียนผิดรูปแบบ → ขึ้น "รหัสภาคเรียนต้องเป็นรูปแบบ เช่น 2569-1" (ใต้ช่องกรอกจะขึ้น "รูปแบบต้องเป็น ปีการศึกษา-ภาคเรียน เช่น 2569-1") — ตรวจว่าเป็นตัวเลข 4 หลัก ขีดกลาง แล้วตามด้วย 1, 2 หรือ 3
  • ใส่รหัสที่มีอยู่แล้ว → ขึ้น "ภาคเรียนนี้มีอยู่แล้ว" — ไม่ต้องเพิ่มใหม่ ให้เลื่อนหารายการเดิมในหน้านี้แล้วกด "ตั้งเป็นปัจจุบัน"
  • ใส่วันสิ้นสุดก่อนวันเริ่ม → ขึ้น "วันสิ้นสุดต้องไม่ก่อนวันเริ่ม" และปุ่มบันทึกจะยังกดไม่ผ่าน
  • โหลดรายการไม่ขึ้น → ขึ้น "โหลดรายการภาคเรียนไม่สำเร็จ" พร้อมปุ่มลองใหม่ — อย่าเพิ่งกด "เพิ่มภาคเรียน" เพราะภาคเรียนเดิมอาจมีอยู่แล้วแต่ยังโหลดไม่ขึ้น
  • หน้านี้ ไม่มีปุ่มแก้ไขหรือลบภาคเรียน — ถ้าใส่รหัสผิด ให้เพิ่มรหัสที่ถูกต้องเพิ่มอีกรายการแล้วตั้งรายการที่ถูกเป็นปัจจุบัน

📷 ยังไม่มีภาพหน้าจอ — หน้านี้เพิ่งถูกเพิ่มเข้าคู่มือ ภาพหน้าจอจะเพิ่มในรอบถ่ายภาพครั้งถัดไป

ใช้เมื่อ: เลิกใช้งานระบบ

ขั้นตอน:

✅ ผลลัพธ์ที่ถูกต้อง: กลับไปหน้าเข้าสู่ระบบ

ภาพ: เมนูบัญชี (มุมขวาบน) — "เปลี่ยนรหัสผ่าน" / "ออกจากระบบ" (ตัวอย่างจากบัญชีโรงเรียน เมนูของผู้ดูแลระบบมีรายการเดียวกัน)

ตารางขอบเขตสิทธิ์ (อ้างอิงด่วน)

คุณเห็นข้อมูลได้แค่ไหน:

ข้อมูล ขอบเขต
นักเรียน / รถ / โรงเรียน / สังกัด เห็นทั้งจังหวัด (ไม่จำกัดขอบเขต)
บัญชีผู้ใช้ทุกบทบาท จัดการได้ทั้งหมด
ประวัติการใช้งาน (audit log) เห็นทั้งระบบ
ตำแหน่งรถ / จุดรับส่ง เห็นทั้งระบบ
รายงาน / การส่งออก ทุกระดับทั้งจังหวัด

สิทธิ์เฉพาะ admin (ไม่มีบทบาทอื่นทำได้): จัดการบัญชีผู้ใช้ทุกบทบาท • เครื่องมือจัดการวงจรชีวิตคนขับ (กู้คืน/ย้าย/ปิด) • อนุมัติคำขอโอนย้ายนักเรียนและคำขอเกี่ยวกับรถ • จัดการ geofence (เมื่อเปิดใช้) • ตรวจสอบจุดรับส่ง/ตำแหน่งรถ (มุมมอง admin) • หน้าวิจัย/snapshot/ส่งออกข้อมูลวิจัย • สุขภาพระบบ

สิ่งที่ทำไม่ได้ (และใครทำแทน):

ทำไม่ได้ หมายเหตุ / ใครทำแทน
ลบบัญชีตัวเอง ระบบป้องกัน (ขึ้น "ไม่สามารถลบตัวเองได้")
เปิดใช้งานบัญชีคนขับซ้ำ ต้องใช้บัญชีหลัก (canonical) หรือใช้ wizard ที่ "สุขภาพข้อมูลคนขับ"
กู้คืนรถที่ทะเบียนชนกับรถที่ใช้งานอยู่ ต้องจัดการรถที่ชนกันก่อน
รีเซ็ตรหัส admin ของตัวเองเมื่อถูกล็อก ต้องให้ admin อีกคนทำ (ควรมี admin สำรอง)
สลับโหมด OBSERVE → ENFORCE จากหน้าจอ ตั้งค่าโดยผู้ดูแลเซิร์ฟเวอร์ (env) เท่านั้น
อนุมัติคำขอเปลี่ยนรายชื่อ (roster) รวมศูนย์ ทำที่ฝั่งโรงเรียน (admin เห็นแค่ตัวเลขเตือน)

ℹ️ ฟีเจอร์ที่แชร์กับบทบาทอื่น: ความพร้อมเปิดใช้งาน และ การเบี่ยงเส้นทาง (ใช้ร่วมกับจังหวัด); QR token (ใช้ร่วมกับขนส่ง)

สรุปปัญหาที่พบบ่อย

อาการ วิธีแก้
สร้าง/รีเซ็ตผู้ใช้แล้วขึ้น "รหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร" ระบบบังคับรหัส ≥8 ตัวทุกครั้งที่ตั้งให้ผู้ใช้ (รวมรหัสชั่วคราว) ห้ามตรงกับชื่อผู้ใช้/ห้ามเดาง่าย — ตั้งรหัสให้ยาวพอแล้วลองใหม่ (ผู้ใช้ยังถูกบังคับเปลี่ยนเองตอน login ครั้งถัดไป)
เปิดใช้งานบัญชีคนขับที่ปิดไว้ไม่ได้ ("ไม่สามารถเปิดใช้งานบัญชีคนขับนี้ได้…") บัญชีซ้ำ/ผูกรถที่ถูกปิด — ใช้บัญชีหลัก (canonical) หรือใช้ wizard ที่ "สุขภาพข้อมูลคนขับ" (งานที่ 6)
อนุมัติคำขอโอนย้ายแล้วขึ้นป้าย "ไม่สำเร็จ" (FAILED) มีรหัสนักเรียนซ้ำที่โรงเรียนปลายทาง หรือข้อมูลไม่ครบ — แก้ที่ปลายทางก่อน
อนุมัติคำขอโอนย้ายแล้วขึ้นป้าย "ต้องตรวจสอบใหม่" (STALE_NEEDS_REVIEW) ข้อมูลนักเรียนเปลี่ยนหลังส่งคำขอ — เปิดดูและตรวจสอบใหม่ก่อนอนุมัติ
กู้คืนรถไม่สำเร็จ ปุ่มอนุมัติเป็นสีจาง (disable) มีรถทะเบียนเดียวกันที่ยังใช้งานอยู่ (canonical conflict) — จัดการรถที่ทะเบียนชนกันก่อน
ลบจุดรับส่ง/ผู้ใช้แล้ว ยังเห็นใน audit log เป็น soft delete โดยตั้งใจ — ซ่อนจากการใช้งานแต่เก็บประวัติไว้ตรวจสอบ
เข้า "จุดเตือนภัย"/"การเบี่ยงเส้นทาง"/"QR รถรับส่ง" แล้ว 404 หรือไม่เห็นเมนู ฟีเจอร์ปิดด้วย feature flag (งานที่ 15) ไม่ใช่บั๊ก — ให้ผู้ดูแลเซิร์ฟเวอร์เปิด flag ก่อน
ถูกเด้งออก/ถูกบังคับเปลี่ยนรหัสกะทันหัน ("เซสชันหมดอายุจากการเปลี่ยนรหัสผ่าน") admin อีกคนรีเซ็ตรหัสคุณ หรือคุณเปลี่ยนรหัสที่เครื่องอื่น — เข้าสู่ระบบใหม่ด้วยรหัสล่าสุด
สร้าง Baseline ซ้ำไม่ได้ ระบบห้ามสร้างซ้ำภายใน 24 ชั่วโมง — รอครบเวลา หรือใช้ baseline ที่มีอยู่
ตัวเลข Error count ในสุขภาพระบบดูไม่ตรง เป็นค่าประมาณจาก login ล้มเหลวเท่านั้น — ใช้ดูแนวโน้ม ไม่ใช่ตัวเลขแม่นยำ
"ตรวจสอบตำแหน่งรถ"/"ตรวจสอบจุดรับส่ง" แก้อะไรไม่ได้ "ตรวจสอบตำแหน่งรถ" อ่านอย่างเดียว; "ตรวจสอบจุดรับส่ง" ใช้กรณีพิเศษ (override) — เพิ่มจุดหลักผ่านบัญชีคนขับ/โรงเรียน

การขอความช่วยเหลือ

  • admin ลืมรหัส / ถูกล็อกออก → ให้ admin อีกคนรีเซ็ตให้ (ถ้าไม่มี admin สำรอง ต้องพึ่งผู้ดูแลเซิร์ฟเวอร์)
  • ต้องการเปิดฟีเจอร์ขั้นสูง (Geofences / การเบี่ยงเส้นทาง / QR / โหมดบังคับใช้ความปลอดภัย) → ติดต่อผู้ดูแลเซิร์ฟเวอร์ให้เปิด feature flag
  • ปัญหาข้อมูลคนขับ/รถที่ซับซ้อน → ใช้หน้า "สุขภาพข้อมูลคนขับ" (งานที่ 6) และ "คำขอเกี่ยวกับรถ" (งานที่ 5) เป็นเครื่องมือหลัก

เวลาแจ้งปัญหากับทีม โปรดส่ง: ชื่อผู้ใช้ (username) ของบัญชีที่เกี่ยวข้อง • เวลาที่เกิดปัญหา • ภาพหน้าจอ (รวมข้อความผิดพลาด) • หน้า/เมนูที่ใช้งานตอนเกิดปัญหา
