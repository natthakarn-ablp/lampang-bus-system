2. **สำรอง + ตรวจสอบ:** `bash scripts/backup-db.sh && bash scripts/verify-latest-backup.sh` (ต้อง RESULT: PASS)
3. **Pin:** ตั้ง `R=<full SHA ที่ review แล้ว>`; `git fetch origin <branch>`; ต้องได้ `git rev-parse FETCH_HEAD == $R` และ `git merge-base --is-ancestor HEAD $R`; วางสคริปต์จาก `$R` ที่ `/home/schoolbus/deploy-state/deploy-backend.sh` แล้วเทียบ sha256 กับ `git show $R:scripts/deploy-backend.sh | sha256sum` ในเครื่องพัฒนา
4. **Deploy:** `EXPECTED_BRANCH=<branch> bash /home/schoolbus/deploy-state/deploy-backend.sh` แบบ detached (`setsid nohup … &`) แล้วอ่าน log · ครั้งที่ marker ไม่ตรง lockfile จะมี staged `npm ci` (~1 นาทีบน server นี้) · ห้ามใช้ `DEPLOY_INSTALL=never` เป็นทางลัดเมื่อ registry ล่ม เว้นแต่พิสูจน์ได้ว่าชุดที่รันอยู่ตรง lockfile (marker ตรง) · ถ้าสคริปต์ ABORT ก่อน reload: ระบบยังรันรุ่นเดิม, node_modules เดิมถูกคืนแล้ว, checkout อาจอยู่ที่รุ่นใหม่ (อ่านบรรทัด ABORT) · ถ้า health ล้มหลัง reload: สคริปต์ถอยกลับให้เอง (`rolled-back` / `rolled-back-unhealthy` ใน history)
5. **Frontend (เมื่อมีไฟล์ใน `frontend/src` เปลี่ยน):** สำรอง `dist` → `npm ls --depth=0` (ถ้ามีปัญหาค่อย `npm ci --no-audit --no-fund`) → `npm run build` → ตรวจ `dist/index.html` และ chunk ที่คาด
6. **ตรวจหลัง:** `/health` (service, commit = release, db true) · `pm2 jlist` (restarts +1) · `tail -2 /home/schoolbus/logs/deploy-history.log` (`end result=ok`) · smoke สาธารณะแบบไม่เขียนข้อมูล (`/`, `/manual/`, chunk ใหม่, `/api/auth/me` → 401) — **ไม่ใช้ login probe** (สร้างแถว `login_lockouts`)
7. **เฝ้าดู 15 นาที:** ตัวอย่างละ 1 นาที: health commit/db, pm2 status/restarts, จำนวนบรรทัด error log, การเชื่อมต่อ
