## 4. สามรอบที่หยุดกลางทาง คือกลไกทำงานถูกต้อง ไม่ใช่เหตุขัดข้อง

รอบ #9 #10 และ #13 จบด้วย `result=failed-before-reload exit=1` คำนี้มีความหมายเฉพาะเจาะจงในสคริปต์นี้ คือ
สคริปต์ตรวจพบปัญหา **ก่อน** สั่ง `pm2 reload` จึงคืน `node_modules` เดิมและออกโดยไม่แตะบริการที่กำลังรัน
ผลคือ production ยังคงรัน commit เดิมต่อไปโดยผู้ใช้ไม่รู้สึกอะไร

ยืนยันจากตัวล็อกเอง บรรทัด `start` ของรอบถัดไปบันทึก `running_before=` เป็น commit **ก่อนหน้า** ไม่ใช่ commit ที่เพิ่ง
ล้มเหลว เช่นรอบ #10 บันทึก `running_before=21196c1` ทั้งที่รอบ #9 พยายามขึ้น `f90eee2` ไปแล้ว แปลว่า `f90eee2`
ไม่เคยได้ให้บริการเลยแม้แต่วินาทีเดียว เช่นเดียวกับรอบ #14 ที่บันทึก `running_before=9edc79f` หลังรอบ #13 ล้ม

เรื่องนี้สำคัญต่อการรับรอง เพราะแปลว่าในวันที่มีการ deploy 14 รอบ **ไม่มีรอบใดทำให้บริการหยุด**
