# คำถามที่ต้องตอบก่อนเปิดกู้รหัสผ่านผ่าน LINE ให้สังกัด จังหวัด และขนส่ง

> จัดทำ 7 กันยายน 2569 ตามการอนุมัติของเจ้าของระบบให้ดำเนินการทั้งสองแนวทาง
> **กลไกพร้อมแล้ว หน้าจอพร้อมแล้ว เหลือคำตอบของคำถามด้านล่างเท่านั้น** เมื่อได้คำตอบ การเปิดใช้เป็นการแก้ไฟล์บรรทัดเดียวต่อบทบาท พร้อมตั้งค่าบนเซิร์ฟเวอร์
> ผู้ตอบ: เจ้าของโครงการ ร่วมกับผู้รับผิดชอบข้อมูลส่วนบุคคล (นางสาวรัชฎาพร สุพรรณ นิติกรชำนาญการพิเศษ)

## ทำไมต้องตอบก่อน

ระบบออกแบบให้แยก **กลไก** ออกจาก **การตัดสินใจ** อย่างตั้งใจ ไฟล์ `backend/src/config/accountRecoveryPolicy.js` เขียนไว้ว่ากลไกเหมือนกันทุกบทบาทและสร้างเสร็จแล้ว แต่คำถามว่าบัญชีหนึ่งเป็นของ "คน" หรือของ "หน่วยงาน" ใครมีอำนาจผูก LINE และจะส่งมอบกันอย่างไรเมื่อเปลี่ยนตัวคน เป็นคำถามของผู้บริหาร ไม่ใช่ของโปรแกรม

ระบบจึงบังคับว่าบทบาทหนึ่งจะเปิดได้ต่อเมื่อ **ตั้งค่าบนเซิร์ฟเวอร์แล้ว และ ยืนยันคำตอบไว้ในไฟล์แล้ว** พร้อมกัน การยืนยันต้องแก้ในไฟล์โค้ด เพื่อให้ปรากฏใน diff คู่กับเอกสารฉบับนี้เสมอ ตั้งค่าเพียงอย่างเดียวเปิดบทบาทไม่ได้

## สิ่งที่ทำไปแล้ว (พร้อมใช้ทันทีที่ได้คำตอบ)

- หน้า "ความปลอดภัยบัญชี" ที่เดิมมีเฉพาะผู้ดูแลระบบ ตอนนี้เปิดให้บทบาทสังกัด จังหวัด และขนส่ง เข้าถึงได้แล้ว และเรียกใช้เส้นทางกลางที่รองรับทุกบทบาท
- หน้านั้นถามเซิร์ฟเวอร์ว่าบทบาทของผู้ใช้เปิดใช้หรือยัง ถ้ายังไม่เปิดจะขึ้นข้อความบอก ไม่ใช่หน้าว่างหรือหน้าพัง
- ข้อความแจ้งเตือนที่เคยระบุว่า "บัญชี LINE นี้ถูกผูกกับผู้ดูแลระบบบัญชีอื่นแล้ว" แก้เป็นข้อความที่ไม่เจาะจงบทบาทและไม่เปิดเผยว่าใครถืออยู่

## คำถามที่ต้องตอบ

| # | คำถาม | ข้อเสนอของผู้ช่วย | คำตอบ |
|---|---|---|---|
| 1 | บัญชีสังกัดเป็นของ **บุคคล** หรือของ **หน่วยงาน** ที่ใช้ร่วมกันหลายคน | เป็นของหน่วยงาน แต่มอบหมายให้เจ้าหน้าที่หนึ่งคนเป็นผู้ถือในแต่ละช่วงเวลา | |
| 2 | ใครมีอำนาจนำ LINE ส่วนตัวมาผูกกับบัญชีสังกัด | เจ้าหน้าที่ผู้ได้รับมอบหมายตามข้อ 1 โดยมีหนังสือหรือบันทึกมอบหมาย | |
| 3 | เมื่อเปลี่ยนตัวผู้รับผิดชอบ ต้องถอด LINE เดิมเมื่อไร และใครเป็นผู้ตรวจสอบ | ถอดในวันที่ส่งมอบงาน โดยผู้ถือเดิมเป็นผู้ถอดเอง และแจ้งจังหวัดทราบ | |

| # | คำถาม | ข้อเสนอของผู้ช่วย | คำตอบ |
|---|---|---|---|
| 1 | บัญชีจังหวัดเป็นของบุคคลหรือของหน่วยงาน | เป็นของหน่วยงาน (สภาองค์กรของผู้บริโภค หน่วยงานประจำจังหวัดลำปาง ถือบัญชี `tcc`) มอบหมายเจ้าหน้าที่หนึ่งคนเป็นผู้ถือ | |
| 2 | ใครมีอำนาจผูก LINE | เจ้าหน้าที่ผู้ได้รับมอบหมาย โดยแจ้งเจ้าของโครงการทราบ | |
| 3 | ขั้นตอนส่งมอบเมื่อเปลี่ยนตัวคน | เช่นเดียวกับสังกัด และแจ้งเจ้าของโครงการ | |

|---|---|---|---|

## ข้อเท็จจริงประกอบการตัดสินใจ

- **หนึ่งบัญชี LINE ผูกได้กับผู้ใช้คนเดียวทั้งระบบ** ถ้าเจ้าหน้าที่คนหนึ่งถือทั้งบัญชีสังกัดและบัญชีอื่น จะผูก LINE เดียวกับทั้งสองบัญชีไม่ได้ ต้องเลือกบัญชีเดียว
- **ผู้ที่ยังไม่เคยเข้าระบบผูก LINE ไม่ได้** เพราะต้องเข้าสู่ระบบด้วยรหัสผ่านก่อน ทั้ง 10 บัญชีของสามบทบาทนี้เคยเข้าระบบแล้ว จึงไม่ติดปัญหานี้
- **ปัจจุบันการกู้รหัสผ่านไม่ใช้รหัสกู้คืน** ตามการตัดสินใจเมื่อ 7 ก.ย. 2569 ลิงก์ใน LINE เป็นด่านเดียว ผู้ที่เข้าถึง LINE ของผู้ถือบัญชีได้จะตั้งรหัสผ่านใหม่ของบัญชีนั้นได้ ทุกครั้งที่รหัสผ่านถูกเปลี่ยน ระบบส่งข้อความแจ้งกลับไปที่ LINE นั้นทันที
- **นโยบายในระบบระบุว่าแต่ละบทบาทควรมีผู้อนุมัติระดับเหนือขึ้นไป** แต่ยังไม่มีโค้ดที่บังคับ ถ้าเปิดตอนนี้ ทุกบทบาทจะกู้เองได้โดยไม่มีใครอนุมัติ เช่นเดียวกับที่ผู้ดูแลระบบเป็นอยู่ ถ้าต้องการขั้นตอนอนุมัติจริงต้องพัฒนาเพิ่ม
- **มีทางเลือกอื่นที่ใช้ได้แล้ววันนี้** จังหวัดรีเซ็ตรหัสผ่านให้สังกัดและขนส่งได้แล้ว (เมนู "บัญชีสังกัดและขนส่ง") จึงไม่ใช่ว่าถ้าไม่เปิดข้อนี้แล้วจะไม่มีทางออก

## เมื่อได้คำตอบแล้วต้องทำอะไร

1. บันทึกคำตอบในตารางข้างบนและลงชื่อผู้ตอบ
2. แก้ `gatesConfirmed` เป็น `true` ของบทบาทที่ได้คำตอบครบ ใน `backend/src/config/accountRecoveryPolicy.js` โดย commit อ้างอิงเอกสารฉบับนี้
3. ตั้งค่าบนเซิร์ฟเวอร์ด้วย `bash scripts/enable-feature-flag.sh` ไม่ได้ เพราะสคริปต์นั้นรู้จักเฉพาะ `FEATURE_*` ของฟีเจอร์หลัก ให้เพิ่มบรรทัด `FEATURE_RECOVERY_AFFILIATION=true` (หรือ `_PROVINCE` / `_TRANSPORT`) ใน `backend/.env` แล้ว `pm2 reload` — สำรองไฟล์ก่อนเสมอ
4. แจ้งผู้ถือบัญชีให้เข้าไปผูก LINE ที่เมนูบัญชี → "ความปลอดภัยบัญชี" **ผู้ที่เข้าสู่ระบบค้างอยู่ต้องออกและเข้าใหม่หนึ่งครั้งเมนูจึงจะขึ้น**
5. ทดสอบกับบัญชีเดียวก่อนขยาย
