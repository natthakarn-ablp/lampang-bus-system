### 0.2 กฎที่ถูกข้ามไปแล้ว ต้องบันทึกย้อนหลัง

`docs/PHASE9_OWNER_OPERATOR_APPROVAL_2026-08.md` หัวข้อ "ไม่อยู่ในขอบเขตอนุมัตินี้" เขียนว่า

> ห้าม import, update, delete, truncate, reset, seed หรือ **migrate production DB โดยไม่มีใบอนุมัติแยก**

**migration 051 ถูก apply ลง production จริงเมื่อ 5 ก.ย. 2569** โดยเจ้าของโครงการอนุมัติด้วยวาจาในเซสชัน
แต่ **ไม่มีใบอนุมัติเป็นลายลักษณ์อักษร** · C0-8 (maintenance window) ยังไม่ถูกตอบ ·

ตัวลดความเสี่ยงมีจริง — additive ล้วน, สามตารางไม่มีข้อมูลนักเรียนหรือผู้ใช้, ตรวจครบ, ผู้ใช้ไม่กระทบ
แต่ต้องมีคนบันทึกย้อนหลังว่าใครอนุมัติ เมื่อไร ไม่งั้นจะเป็น production change ที่ไม่มีที่มาในบันทึกปิดโครงการ

## 4. บทเรียนจากเซสชันนี้ที่ควรพกไปด้วย

1. **เอกสารในโปรเจกต์นี้ overclaim เป็นระบบ** — รอบตรวจก่อนหน้า agent หักล้างข้อสรุปรอบแรก 20 จาก 24 ข้อ
   รอบนี้แก้คำตัดสิน 7 จาก 15 เฟส ลดระดับเกือบทั้งหมด **อย่าเชื่อ checkbox หรือคำว่า "เสร็จแล้ว" ในเอกสาร ให้เปิดโค้ดดู**

2. **แยกสี่อย่างนี้เสมอ** — โค้ดมีอยู่ / มีเทสต์ / รันบน production / มีคนเซ็นรับ
   เฟสหนึ่งเป็น 100% ข้อแรกและ 0% ข้อสุดท้ายได้สบาย ๆ

3. **jest บนเครื่อง Windows นี้ถูกฆ่ากลางคัน exit 127 ประมาณครึ่งหนึ่งของรอบ** (FAIL=0, log ขาด)
   ให้ retry 3–5 รอบ ถือว่าตกจริงเมื่อมีบรรทัด `FAIL` หรือมี `Tests:` summary
   **แต่ถ้าตายทุกรอบที่จุดเดิม นั่นคือบั๊กจริง ไม่ใช่ flake** — ดู `[[jest-suite-flake-windows]]` ใน memory

4. **เทสต์ที่อ่าน `outputs/` จะให้ผลต่างกันทุกเครื่อง** เพราะโฟลเดอร์นั้นอยู่ใน gitignore
   เคยทำให้ deploy production หยุดกลางคัน แก้แล้วใน `93e7b41` และ `208e883`
   ถ้าเขียนเทสต์ใหม่ที่แตะ `outputs/` ให้ระวังข้อนี้

5. **`vite build` + `check:hybrid-ui` + `check:labels:strict` ผ่านหมดได้ทั้งที่หน้าพังจริง**
   ตัวที่จับได้คือเปิดในเบราว์เซอร์ (`FormField` รับ `children` เป็น render prop ไม่ใช่ node)

6. **migration ต้องเขียนไว้ 3 ที่** — `migrations/*.sql`, `backend/tests/schema.sql` (test DB สร้างจากไฟล์นี้
   ไม่ใช่จาก migrations) และด่าน boot ใน `index.js` · ลืมข้อกลางแล้ว CI แดงทั้งชุด
   มีเทสต์กันไว้แล้วที่ `backend/tests/sharedStateDeployGuard.unit.test.js`

7. **`deploy-backend.sh` ไม่รัน migration** — เป็น `git pull` + ตรวจ + unit test + `pm2 reload` เท่านั้น
   ต้องรัน migration เองก่อนเสมอ ดู `docs/ops/deploy-runbook-051-shared-security-state.md`
