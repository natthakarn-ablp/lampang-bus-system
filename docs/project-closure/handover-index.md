# สารบัญการส่งมอบความรู้ — School Safe Connect ลำปาง

> สร้าง 8 กันยายน 2569 · ตอบงาน H14-5 ในแผน `execution-plan-to-completion-2026-09-04.md`
> เอกสารนี้ **ไม่ใช่การส่งมอบ** และไม่ใช่การรับรองว่าเอกสารที่อ้างถึงถูกต้องครบถ้วน
> เป็นเพียงแผนที่บอกว่าความรู้แต่ละด้านอยู่ที่ไฟล์ใด เพื่อไม่ให้การส่งมอบเริ่มจากหน้ากระดาษเปล่า
> ทุกไฟล์ในตารางถูกตรวจแล้วว่ามีอยู่จริง ณ วันที่สร้างเอกสาร

## 1. ผู้รับมอบต้องทำอะไรกับเอกสารนี้

แผนกำหนดว่าการส่งมอบความรู้จะปิดได้ต่อเมื่อ **ผู้รับมอบยืนยันว่าใช้เอกสารทำงานได้จริง โดยเดินผ่านอย่างน้อยหนึ่งรอบ**
ไม่ใช่แค่ได้รับไฟล์ ตารางในข้อ 3 จึงมีช่อง "เดินผ่านแล้ว" ให้ผู้รับมอบกรอกเอง

## 2. เริ่มอ่านจากตรงไหน

ถ้ามีเวลาอ่านเพียงสามฉบับ ให้อ่านตามลำดับนี้

1. `docs/OPERATOR_RUNBOOK.md` — งานประจำวันของผู้ดูแลระบบ
2. `docs/ops-backup-restore.md` — วิธีสำรองและกู้คืนข้อมูล ซึ่งเป็นสิ่งเดียวที่กู้ความผิดพลาดร้ายแรงได้
3. `docs/INCIDENT_PDPA_SOP_2026-08.md` — ทำอย่างไรเมื่อเกิดเหตุ โดยเฉพาะเหตุที่กระทบข้อมูลส่วนบุคคลของเด็ก

## 4. สิ่งที่ยังไม่มีเอกสาร และต้องรู้ว่าไม่มี

การส่งมอบที่ซื่อสัตย์ต้องบอกด้วยว่าอะไรยังไม่มี ไม่ใช่แค่ชี้ว่าอะไรมี

| หัวข้อ | สถานะ |
|---|---|
| เอกสารสถาปัตยกรรมระบบแยกฉบับ | **ไม่มี** ความรู้กระจายอยู่ในคู่มือผู้ดูแลระบบและในโค้ด |
| การประเมินผลกระทบด้านข้อมูลส่วนบุคคล (DPIA) | **ไม่มี** มีเพียงขั้นตอนรับมือเหตุการณ์ |
| บันทึกการอบรม (ผู้เข้าอบรม แบบฝึก ผลประเมิน) | **ไม่มี** ยังไม่มีการอบรมเกิดขึ้น |
| ผลการทดสอบรองรับผู้ใช้จำนวนมากจริง | **ไม่มี** มีเพียงการซ้อมบนเครื่องพัฒนา ซึ่งเอกสารนั้นระบุเองว่าไม่ใช่หลักฐาน |
| ผลการทดสอบกับผู้ใช้จริงครบทุกบทบาท | **ไม่มี** `docs/UAT_SIGNOFF_2026-08.md` ยังเป็นแบบฟอร์มเปล่า |
| ผู้ดูแลและงบประมาณหลังส่งมอบ | **แบบฟอร์มเปล่า** ที่ `docs/ops/post-handover-ownership.md` |
