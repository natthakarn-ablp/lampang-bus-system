## ขั้นตอนปล่อยที่ผู้ดูแลดำเนินการภายหลัง

1. ให้เจ้าของ review และ merge PR #46 กับ PR #50 เข้า `feat/tracking-security-hardening` หลัง required checks ผ่าน
2. บน checkout ที่ผู้ดูแลใช้ปล่อย ให้รัน `git fetch origin` แล้ว checkout SHA เต็มที่เจ้าของอนุมัติหลัง merge ด้วย `git checkout --detach <TARGET_SHA>`; บันทึก SHA นี้เป็น release target
3. รัน `cd backend && npm ci`; จากนั้น `cd ../frontend && npm ci && npm run build`; ตรวจว่า build สำเร็จจาก SHA เดียวกัน
4. ก่อน reload ให้ผู้ดูแลตรวจ health ปัจจุบัน, deploy lock, process และ backup ตาม runbook ที่อนุมัติ
5. จาก root ของ checkout รัน `pm2 reload ecosystem.config.js` ตามชื่อแอปใน ecosystem (`schoolbus-backend`)
6. เช็คลิสต์หลังปล่อย:
   - `GET /api/health` ตอบ HTTP 200 และค่า `commit` ตรงกับ `<TARGET_SHA>`
   - ชื่อ `index-*.js` ใน HTML ที่เว็บส่งจริงตรงกับไฟล์ที่ build จาก SHA นี้
   - บัญชีครูสายชั้นสำหรับ UAT เรียก `/api/documents/...` แล้วได้ HTTP 403 และรหัส `FULL_SCHOOL_SCOPE_REQUIRED`
   - ทดสอบล็อกอินครบทุก role ด้วยบัญชี UAT ที่ได้รับอนุญาต
   - `pm2 logs schoolbus-backend` ไม่มี error ใหม่ที่สัมพันธ์กับ release
7. บันทึกเวลา, ผู้ปฏิบัติงาน, SHA, ผล health/assets/access/login/log checks และข้อมูล backup ที่ได้รับอนุญาตใน deploy record; ช่องที่ไม่มีหลักฐานให้ระบุ NOT VERIFIED

ขั้นตอนทั้งหมดข้างต้นยังไม่ถูกดำเนินการในงานนี้
