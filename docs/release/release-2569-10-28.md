## Migration และข้อกำหนดก่อนเปิดใช้

**ไม่มี migration ใหม่** ในช่วงตั้งแต่ `658f908` ถึง branch ฐานที่ใช้เตรียม release นี้

Migrations 052 และ 053 อยู่ในประวัติก่อนหน้า แต่สถานะบน production ยังไม่ยืนยัน เอกสาร deploy เดิมระบุว่าต้องตรวจจาก production database โดยผู้ดูแลที่ได้รับอนุญาต และ deployment script ไม่ได้ apply migration ให้อัตโนมัติ ก่อนเปิดใช้ policy-notice flow หรือ code path ที่ต้องใช้สองตารางนี้ ผู้ดูแลต้องยืนยันสถานะทั้งคู่จาก production ตาม runbook ที่ได้รับอนุมัติ ห้ามตีความว่า migration ถูก apply แล้วจากการมีไฟล์หรือจาก health check

## ขั้นตอนปล่อยที่ผู้ดูแลดำเนินการภายหลัง

1. ให้เจ้าของ review และ merge PR #46 กับ dependency PR เข้า `feat/tracking-security-hardening` หลัง required checks ผ่าน
2. Fetch branch หลัง merge, บันทึก release SHA เต็ม และยืนยันว่า working tree สะอาดและ branch ตรงกับ SHA ที่จะปล่อย
3. ก่อน server operation ให้ผู้ดูแลตรวจ health ปัจจุบัน, deploy lock, process, และ backup ตาม runbook; งานเตรียมเอกสารนี้ไม่ได้ตรวจ server และไม่มีผล server ใหม่
4. ยืนยัน production status ของ migrations 052/053 จากฐานข้อมูลตามขั้นตอนที่อนุมัติ หากยังยืนยันไม่ได้ ให้หยุดก่อนเปิด policy-notice flow หรือ code path ที่ต้องใช้ตารางเหล่านั้น
5. ปล่อย backend ด้วย `scripts/deploy-backend.sh` ตาม runbook ของระบบ; script นี้ตรวจโค้ดและ health แต่ไม่ apply migrations
6. ปล่อย frontend จาก SHA เดียวกันตาม `docs/ops/frontend-publish-2026-10-17.md` เมื่อ backend ผ่าน health แล้วเท่านั้น และบันทึกผลจริง
7. ตรวจ `/api/health`, login และหน้าที่ได้รับผลกระทบหลังปล่อย แล้วบันทึก commit ที่ตอบจริง, ผู้ปฏิบัติงาน, เวลา, backup, migration evidence, health และผล smoke ใน deploy record

ขั้นตอนทั้งหมดข้างต้นยังไม่ถูกดำเนินการในงานนี้

## Rollback

ใช้ขั้น rollback ใน `scripts/deploy-backend.sh` และ runbook ที่เกี่ยวข้อง โดยอ้างอิง **commit ที่ health endpoint ยืนยันว่ากำลังรันก่อนเริ่มปล่อย** เป็น rollback reference ห้ามสมมติว่า `658f908` ยังเป็นรุ่นที่รันอยู่ หากผู้ดูแลตรวจแล้วว่าเป็น commit ที่กำลังรัน ให้บันทึกเป็น rollback SHA; มิฉะนั้นใช้ SHA ที่ตรวจพบจริง

ไม่มี migration ใหม่ใน release range นี้ จึงไม่มี migration rollback ใหม่ที่ต้องรัน หากตรวจพบว่ามีการใช้ 052/053 อยู่แล้ว ห้าม drop ตารางระหว่าง rollback โค้ดโดยไม่มีแผนเฉพาะและการอนุมัติผู้ดูแล
