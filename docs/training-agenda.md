## 1. Training Objective

หลังจบ workshop ผู้เข้าร่วมจะสามารถ:

1. เข้าสู่ระบบและออกจากระบบในบทบาทของตนเองได้
2. ใช้ฟังก์ชันหลักของบทบาทตนเองได้โดยไม่ต้องอ่านคู่มือซ้ำ
3. รู้ขอบเขตข้อมูลที่ตนเองเห็น (และไม่เห็น) ตามนโยบายระบบ
4. รู้ว่าควร / ไม่ควรทำอะไรในระบบ (ข้อควรระวัง PDPA, override, การลบข้อมูล)
5. รู้ขั้นตอนแจ้งปัญหาเมื่อพบ bug หรือเหตุผิดปกติ
6. (สำหรับครู/โรงเรียน) ใช้ฟีเจอร์ "ยืนยันแทนคนขับ" อย่างเหมาะสม
7. (สำหรับคนขับ) เช็คอิน/เช็คเอาท์/แจ้งเหตุฉุกเฉินบนมือถือได้
8. (สำหรับผู้ปกครอง) ผูกบัญชี LINE และดูสถานะบุตรหลานได้

## 2. Target Participants

| กลุ่ม | จำนวนแนะนำต่อรอบ | บทบาท |
|---|---|---|
| โรงเรียน | 1–2 ต่อโรงเรียน | school full / grade-scoped teacher |
| คนขับรถ | ทั้งหมดในโครงการ | driver |
| เขตพื้นที่ / สังกัด | 1 ต่อเขต | affiliation |
| จังหวัด | 1–2 คน | province |
| ขนส่ง | 1–2 คน | transport |
| ผู้ปกครอง (ตัวแทน) | 2–3 คน | parent / LINE (เพื่อ feedback) |

แนะนำแยกรอบเป็น 2 กลุ่ม:
- **รอบ A**: โรงเรียน + คนขับ (operational hands-on)
- **รอบ B**: เขต + จังหวัด + ขนส่ง (overview + dashboards)

---

## 3. Duration

- **รวม**: 60–90 นาทีต่อรอบ
- เผื่อ buffer 15 นาทีก่อนเริ่มเพื่อตั้งค่าอุปกรณ์
- เผื่อ Q&A 15 นาทีหลังจบ

## 5. Role-based Practice Tasks

แต่ละบทบาททำ task ต่อไปนี้ในระหว่าง workshop (มีบัญชี `__TRAIN_*` เตรียมไว้
สำหรับ practice):

### 5.1 Province / Affiliation
1. Login เข้าสู่ระบบ → ดู 5-card dashboard
2. กดเข้าโรงเรียน 1 โรงเรียน → ดูสถานะวันนี้
3. เปิด live vehicle map → กดที่ pin ของรถ 1 คัน
4. เปิด `/reports/daily` → export Excel
5. (Affiliation เท่านั้น) เปรียบเทียบโรงเรียน 2 โรงเรียน
6. Logout

### 5.2 Transport
1. Login → ดู dashboard (ไม่มีตัวเลขนักเรียน — สังเกตว่าเป็นการออกแบบ)
2. เปิด document expiry cards → ดูรถใกล้หมดประกัน
3. บันทึก inspection 1 รายการ (test vehicle)
4. เปิด pickup map → สังเกตว่าไม่มีชื่อนักเรียน (PDPA)
5. Export รายงานตรวจสภาพ
6. Logout

### 5.3 School — full account
1. Login → ดู session hero cards + action row
2. ค้นหานักเรียน 1 คน → เปิดรายละเอียด
3. เพิ่มนักเรียนทดสอบ 1 คน (prefix `__TRAIN_`) → soft-delete กลับ
4. เปิด vehicle management → ดูรายการรถ
5. เปิด `/reports/daily` → export PDF
6. **"ยืนยันแทนคนขับ" สำหรับนักเรียนทดสอบ** — สังเกตว่า:
   - ต้องกรอกเหตุผล
   - ผู้ปกครอง (ที่ผูก LINE) ของนักเรียนนั้นได้รับ push (ถ้ามี)
   - audit log บันทึก
7. Logout

### 5.4 School — grade-scoped teacher
1. Login (บัญชีครู ป.X)
2. สังเกตป้ายขอบเขตบนแถบบนสุด (แสดงเมื่อใช้จอคอมพิวเตอร์) → "ขอบเขตสายชั้น ป.X" ส่วนบัญชีโรงเรียนเต็มสิทธิ์จะขึ้น "ขอบเขตโรงเรียน" และในหน้ากลุ่มโรงเรียน/รายงานจะมีป้ายอีกจุดว่า "ขอบเขตข้อมูล: ป.X"
3. ค้นหานักเรียน → เห็นเฉพาะชั้นของตนเอง
4. ตรวจสอบว่าปุ่ม "เพิ่มนักเรียน" / "จัดการรถ" / "ยืนยันแทนคนขับ" ไม่ปรากฏ
5. เปิด `/reports/daily` ที่ scope ของชั้นนั้น
6. Logout

### 5.5 Driver
1. Login ด้วย **ทะเบียนรถ** (ภาษาไทย เว้นวรรค 1 ที่)
2. ดู pretrip status pill + remaining counter
3. ดู roster ของนักเรียนทั้งคัน
4. เช็คอินนักเรียน 1 คน → ดูสถานะเปลี่ยน
5. เช็คเอาท์ → ดูสถานะเปลี่ยน
6. (Simulate) ฝึกกดปุ่มฉุกเฉิน (ใช้ test scenario; **ห้ามใช้จริง**)
7. ดูแถวที่มี chip "ครูยืนยันแทนแล้ว" (ถ้ามี)
8. Logout

### 5.6 Parent / LINE OA
1. เพิ่มเพื่อนบอท `@943glwjf` (รถรับส่งนักเรียน) ในแอป LINE
2. พิมพ์ `ผูกบัญชี` → กดปุ่ม "📝 เปิดฟอร์มผูกบัญชี"
3. กรอกเบอร์โทร + รหัสนักเรียน → success
4. พิมพ์ `สถานะ` → ดู Flex card บุตรหลาน
5. (ถ้าผู้ปกครองมีลูกหลายคน) — ตรวจว่าเห็นครบทุกคน
6. พิมพ์ `ยกเลิกผูกบัญชี` → ยืนยัน
7. พิมพ์ `ผูกบัญชี` ใหม่ — ตรวจว่าผูกซ้ำได้ (idempotent)

## 6. Q&A — คำถามที่มักพบ

| คำถาม | คำตอบสั้น |
|---|---|
| ลืมรหัสผ่าน ทำอย่างไร? | ติดต่อ admin โรงเรียนหรือ admin ระบบ ให้รีเซ็ตให้ |
| ครูสายชั้นทำไมไม่เห็นปุ่ม "ยืนยันแทนคนขับ"? | เป็นการออกแบบ — เฉพาะบัญชีหลักโรงเรียนทำได้ |
| ขนส่งทำไมไม่เห็นจำนวนนักเรียน? | นโยบาย PDPA — ขนส่งดูแลเฉพาะข้อมูลรถ |
| ผู้ปกครองมีลูกหลายคน เบอร์เดียวกัน — ผูก LINE หลายครั้ง? | ไม่ต้อง — ผูกครั้งเดียว เห็นลูกทุกคนของเบอร์นั้น (phone-based resolver) |
| ลบนักเรียน/รถผิดทำอย่างไร? | เป็น soft-delete — admin/operator กู้คืนได้ผ่าน UPDATE flag หรือ restore backup |
| เห็นว่าโรงเรียนไม่มีนักเรียน — เป็น bug? | อาจถูกซ่อนจาก global reset; ติดต่อ operator ตรวจสอบใน DB |
| LINE ไม่ตอบเลย | ตรวจว่า bot active + bot ที่ใช้ถูกตัว (`@943glwjf`); ถ้ายังไม่ตอบติดต่อทีมเทคนิค |
| ใช้บน iOS / Android ต่างกันไหม? | ไม่ต่าง — responsive web; LINE flow ทำงานเหมือนกันทั้งสอง |

## 7. Post-training Feedback

ขอให้ผู้เข้าร่วมตอบ 5 ข้อหลังจบ workshop (Google Form หรือกระดาษก็ได้):

1. ความเข้าใจในระบบหลัง training (1–5)
2. ความง่ายในการใช้งานบทบาทของตนเอง (1–5)
3. ฟีเจอร์ที่คิดว่าจะใช้มากที่สุด
4. ฟีเจอร์ที่คิดว่ายังขาดหรือต้องปรับ
5. ข้อเสนอแนะอื่น ๆ

รวบรวม feedback แล้ว:
- จัดลำดับความสำคัญ → ใส่ใน sprint backlog ถัดไป
- ถ้ามีปัญหาด่วน → escalate ตาม severity ใน [docs/go-live-handoff.md §8.1](go-live-handoff.md)
