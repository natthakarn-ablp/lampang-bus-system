# ขั้นตอนงานเจ้าหน้าที่ขนส่ง: ตรวจรถและแก้ข้อมูล

เอกสารนี้ใช้กับรุ่นที่มีเมนู **ตรวจรับรองรถ** และปุ่ม **ส่งออกรายงานรถ CSV** บนหน้าภาพรวม การแก้ข้อมูลจริงต้องอ้างอิงเอกสารรถและผู้มีหน้าที่รับรอง ไม่เลือกวันหมดอายุที่ถูกต้องจากฐานข้อมูลอย่างเดียว

| งาน | บัญชีขนส่งทำได้ | ขอบเขต |
|---|---|---|
| ดู | รถและคำขอตรวจทั้งจังหวัด ผลตรวจ เอกสารประกอบ คนขับ และจำนวนผู้โดยสารแบบรวมในคำขอ | ไม่มีรายชื่อนักเรียนในหน้าขนส่ง; การเปิดไฟล์เอกสารต้องมีเหตุจำเป็น |
| แก้ | ตรวจเอกสาร รับรองคุณสมบัติคนขับ และบันทึกผลตรวจของงานที่ตนเริ่ม | ข้อมูลทะเบียน/โรงเรียน/นักเรียนให้เจ้าของข้อมูลแก้ต้นทาง; ผลคิวที่สรุปแล้วแก้ตรงไม่ได้ |
| รับรอง | เริ่มตรวจคำขอที่พร้อม ลง checklist และสรุป PASSED, FAILED, NEEDS_FIX หรือ PENDING | คำขอหนึ่งเปิดการตรวจได้ครั้งเดียว; ผู้เริ่มตรวจเท่านั้นสรุปผลได้ |
| ส่งออก | รายงาน CSV ที่มีทะเบียน ประเภทรถ ผลตรวจ และวันหมดอายุเอกสาร/ผลตรวจ | ไม่มีชื่อนักเรียน รหัสนักเรียน จำนวนผู้โดยสาร เบอร์โทร หมายเหตุ หรือไฟล์หลักฐาน; จำกัดอัตราและบันทึก EXPORT |

## ลำดับงานประจำวัน

1. เปิด **ภาพรวมตรวจสภาพรถ** ดูกลุ่มเร่งด่วนและป้าย **ข้อมูลผลตรวจไม่ตรงกัน** ก่อน กลุ่ม “พร้อมใช้” ต้องมีผลรับรองผ่าน เอกสารไม่หมดอายุ และไม่มีงานตรวจค้าง
2. เปิด **ตรวจรับรองรถ** แล้วค้นทะเบียนหรือคำขอ ตรวจข้อมูลรถ เอกสาร และคนขับทุกคนที่ได้รับมอบหมาย รวมคนขับสำรอง
3. ถ้าทะเบียน เจ้าของรถ โรงเรียน หรือเอกสารไม่ตรง ให้โรงเรียนหรือผู้ดูแลข้อมูลแก้ต้นทาง แล้วส่งคำขอใหม่ ขนส่งไม่แก้ข้อมูลนักเรียนหรือทะเบียนโรงเรียนแทน
4. เจ้าหน้าที่คนเดียวกดเริ่มตรวจ ลง checklist ให้ครบ ข้อที่ไม่ผ่านต้องมีรายละเอียด ผล “ผ่าน” ต้องมีวันหมดอายุ ถ้ามีผู้อื่นรับงานอยู่ ระบบแสดงชื่อผู้รับงานและไม่ให้สรุปแทน
5. หลังสรุป ให้ตรวจผลในคิวและหน้าภาพรวมอีกครั้ง ถ้าผลจากบันทึกเดิมกับคิวรับรองต่างกัน รถจะถูกทำเครื่องหมายให้ตรวจสอบ และไม่ถูกนับเป็น “พร้อมใช้”
6. หากต้องนำข้อมูลไปตรวจภายนอก กด **ส่งออกรายงานรถ CSV** จากภาพรวม ใช้ไฟล์เฉพาะงานรถและผลตรวจ ห้ามใช้รายงานนักเรียนของบทบาทอื่น

## เมื่อพบข้อมูลผิด

| สถานการณ์ | วิธีแก้ |
|---|---|
| งานกำลังตรวจแต่ลงผิดหรือทำต่อไม่ได้ | ผู้เริ่มตรวจยกเลิกงานที่ค้าง; ผู้ดูแลระบบยกเลิกแทนได้เมื่อมีเหตุผล แล้วเริ่มใหม่จากคำขอเดิม |
| ผล NEEDS_FIX หรือ PENDING | ให้เจ้าของข้อมูลแก้หลักฐานหรือข้อมูลต้นทาง แล้วตรวจรอบใหม่ในคำขอที่ยังเปิดอยู่ |
| ผล PASSED หรือ FAILED ที่สรุปแล้วผิด | เก็บผลเดิมไว้ ให้โรงเรียนส่งคำขอใหม่และตรวจใหม่ ห้ามแก้หรือลบผลเดิมผ่านหน้าบันทึกแบบเก่า |
| ผลคิวรับรองกับบันทึกเดิมไม่ตรงกัน | ตรวจเอกสารฉบับจริงและลำดับเหตุการณ์ก่อน แสดงรายการเป็นข้อขัดแย้ง ห้ามเดาว่าวันใดถูกต้องหรือแก้ฐานข้อมูลโดยตรง |
| ผลตรวจแบบเดิมที่ยังไม่เคยเข้าคิวรับรองผิด | ผู้บันทึกหรือ admin แก้ได้ตามสิทธิ์; การลบและ audit/คำนวณสถานะทำในธุรกรรมเดียวกัน |

หน้าบันทึกผลตรวจแบบเดิมยังใช้เพื่ออ่านประวัติและรองรับข้อมูลเก่า เมื่อรถมีผลจากคิวรับรองแล้ว ระบบปิดการเพิ่ม/แก้/ลบผลผ่านหน้านี้เพื่อไม่ให้แหล่งข้อมูลสองชุดขัดกัน
