# แผนที่การเปลี่ยนเส้นทาง (Redirect Map)

> สถานะ: บันทึกสิ่งที่โค้ด **ทำอยู่จริง** ณ 2026-09-05 — ไม่ใช่สิ่งที่ตั้งใจจะทำ
> ที่มาของทุกแถว: `frontend/src/App.jsx` (105 `<Route>`) และ `frontend/src/components/Sidebar.jsx`
> ตรวจซ้ำได้ด้วย `grep -n 'path=' frontend/src/App.jsx` และ `grep -n 'Navigate' frontend/src/App.jsx`

เอกสารนี้มีไว้เพื่อสองอย่าง

1. เวลาเปลี่ยนโครงเมนู (A2-1) จะได้รู้ว่า path เดิมที่ผู้ใช้ bookmark ไว้จะไปโผล่ที่ไหน
2. เวลาเปิด/ปิด feature flag จะได้รู้ว่าหน้าไหน "หาย" จากเมนูแต่ยังเข้าได้ด้วยการพิมพ์ URL

## 2. Redirect ที่มีอยู่จริงทั้งหมด (6 เส้น)

ทุกเส้นใช้ `replace` จึงไม่ทิ้งรายการไว้ใน history — กดย้อนกลับแล้วไม่วนกลับมาที่ path เดิม

| path เดิม | ปลายทาง | บรรทัด | เหตุผล |
|---|---|---|---|
| `/driver/leaves` | `/driver` | `App.jsx:220` | ย้ายการลาไปรวมในหน้าหลักคนขับ |
| `/school/status` | `/school` | `App.jsx:242` | สถานะวันนี้ถูกยุบเข้า dashboard |
| `/school/missing` | `/school` | `App.jsx:244` | รายชื่อที่ยังไม่ถูกเช็กถูกยุบเข้า dashboard |
| `/parent/link/link` | `/parent/link` | `App.jsx:454` | path ซ้ำคำจากลิงก์ LINE รุ่นเก่า |
| `/link` | `/parent/link` | `App.jsx:455` | ลิงก์สั้นที่เคยส่งใน LINE |
| `*` (ไม่ตรงอะไรเลย) | `/` | `App.jsx:458` | catch-all แล้วให้ `/` ส่งต่อตาม `ROLE_HOME` |

**ข้อสังเกตเรื่อง catch-all:** พิมพ์ URL ผิดจะไม่เห็นหน้า 404 แต่จะเด้งกลับหน้าแรกของบทบาทตัวเอง
ผู้ใช้ที่ยังไม่ล็อกอินจะเด้งไป `/login` (`App.jsx:132`, `:186`)
ผลข้างเคียงคือ **ระบบไม่มีหน้า 404 ที่ผู้ใช้จะได้เห็นเลย** — ถ้าเมนูใหม่ทำลิงก์พัง ผู้ใช้จะเห็นแค่หน้าแรก
ไม่ใช่ข้อความบอกว่าลิงก์เสีย จึงตรวจจับได้ยากจากรายงานของผู้ใช้

## 3. ช่องว่างที่ยังไม่ได้ปิด — flag ซ่อนเมนูได้ แต่ไม่ได้ปิดเส้นทาง

`Sidebar.jsx:163-192` ซ่อนลิงก์ในเมนูเมื่อ flag ปิด (Phase 11A audit fix M7) เพื่อไม่ให้ผู้ใช้กดแล้วเจอ 404

```
'/admin/geofences'              → geofence
'/admin/route-deviations'       → routeDeviation
'/driver/shift'                 → driverShiftSelection
'/driver/vehicle-registration'  → driverRegistration
'/driver/applications'          → driverRegistration
'/school/registration-review'   → driverRegistration
'/participation'                → participationCases   (เพิ่ม 2026-09-05)
```

แต่ `App.jsx` **ไม่ได้อ้างถึง `features` เลยแม้แต่ครั้งเดียว** (`grep -c features frontend/src/App.jsx` = 0)
แปลว่าทั้ง 7 path ยัง `<Route>` อยู่เสมอ ไม่ว่า flag จะเปิดหรือปิด

ผลที่ตามมาเมื่อ flag ปิด แล้วผู้ใช้เข้าถึง path ตรง ๆ (bookmark, ลิงก์ที่เคยส่งกันไว้, พิมพ์เอง):

- เมนูไม่มีลิงก์ → หาไม่เจอ (เจตนาถูกต้อง)
- แต่ path ยังเข้าได้ → หน้าโหลดขึ้นมา แล้วยิง API ที่ `app.js` ไม่ได้ mount (`app.js:196-197` mount `/api/participation` ต่อเมื่อ flag เปิด — โมดูลอื่นก็รูปแบบเดียวกัน)
- ผู้ใช้เห็นหน้าเปล่าหรือ error state โดยไม่มีคำอธิบายว่า "ฟีเจอร์นี้ยังไม่เปิด"

**สิ่งที่หน้า participation ทำไปก่อนแล้วครึ่งทาง:** หน้ารายการตรวจข้อความ 404 ที่ได้กลับมา
แล้วขึ้นกล่องบอกว่า "ยังไม่ได้เปิดใช้งานส่วนนี้" แทนที่จะแสดงตารางว่างซึ่งอ่านได้ว่า "ไม่มีเรื่อง"
เป็นการแก้อาการที่แย่ที่สุด (เข้าใจผิดว่าไม่มีข้อมูล) แต่ยังไม่ได้แก้ต้นเหตุ (path ยังเข้าได้)

**ข้อเสนอ (ยังไม่ได้ทำ — ต้องรอ decision C0-3 เรื่องโครงเมนู):**
ให้ `App.jsx` อ่าน `features` จาก `useAuth()` แล้ว redirect ทั้ง 7 path นี้ไป `ROLE_HOME` ของผู้ใช้เมื่อ flag ปิด
จะได้พฤติกรรมเดียวกับเมนู คือ "ยังไม่เปิด = ไม่มีอยู่" แทนที่จะเป็น "มีอยู่แต่พัง"

ที่มาของ `features`: มาจาก response ตอน login (`backend/src/routes/auth.routes.js:226` ส่ง `env.features`)
ฝั่งหน้าบ้านเก็บลง `localStorage` แล้วอ่านผ่าน `useAuth()` (`frontend/src/hooks/useAuth.jsx:19,28,34`)
จึงอ่านค่าได้โดยไม่ต้องเพิ่ม API ใหม่

## 4. เมนูที่ซ่อนด้วยเหตุผลอื่น (ไม่ใช่ flag)

| เงื่อนไข | ผลกับเมนู | ที่มา |
|---|---|---|
| `driverRegistration` เปิด | ซ่อน `/driver/requests` เพื่อไม่ให้คนขับเห็นปุ่มคล้ายกันสองปุ่ม | `Sidebar.jsx:189` |
| บัญชีครูประจำสายชั้น (`grade_scope`) | ซ่อน path ใน `TEACHER_BLOCKED_PATHS` รวมถึง `/school/registration-review` | `Sidebar.jsx:~150-160` |

ทั้งสองกรณีเป็นการซ่อนเมนูอย่างเดียวเช่นกัน — path ยังเข้าได้ตรง ๆ
กรณีครูประจำสายชั้นมีการกันซ้ำที่ backend แล้ว (`registration.routes.js` 403 ทั้งโมดูล) จึงไม่ใช่ช่องโหว่สิทธิ์
แต่ยังเป็นทางตันที่ไม่มีคำอธิบาย

---

## 5. สิ่งที่เอกสารนี้ยังไม่ครอบคลุม

- ไม่ได้ทดสอบว่าแต่ละ redirect ทำงานจริงในเบราว์เซอร์ — เป็นการอ่านจากซอร์สทั้งหมด
  (`scripts/ui-redesign/route-matrix.mjs` มีอยู่แล้วแต่ยังไม่ถูกใช้กับรายการนี้)
- ยังไม่มีแผนที่ path เดิม → path ใหม่ สำหรับ A2-1 เพราะโครงเมนูใหม่ยังไม่ถูกอนุมัติ (รอ C0-3)
  เมื่ออนุมัติแล้ว ตารางในหัวข้อ 2 คือที่ที่ต้องเพิ่มแถวใหม่ลงไป
